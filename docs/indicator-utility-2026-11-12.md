- 审计对象：`backend/app/signals/analysis/` 下的全部技术指标与由其派生的信号，以及 `protection/`、`rebalance_logic` 里作为风控/过滤使用的指标

## 3. 逐个裁决

### 3.1 可用（有正期望迹象，但仍需样本外）
- **RSI 背离（4h）**：+41.8bp/6 根，扣成本 +33.8bp，胜率 56.6%，按币 bootstrap 区间 [+2, +93]、P(>0)=98%。
  是全部指标里唯一 bootstrap 下界为正的。但 173 笔、单一 180 天样本、30 次指标×周期比较，
  多重检验后仍可能是一次「幸运」。**结论：值得独立小仓验证，不构成放大仓位的理由。**
  注意它靠「空头」赚钱（空 +17.1 / 多 -8.7），和「顶背离比底背离可靠」的经验一致，但也可能是这段行情的特征。
- **EMA120 + 0.4ATR（4h）**：+47.8bp/6 根，但 90 笔、bootstrap [-13, +124]，说明区间跨零。
  从「配置 1.0ATR 时半年只触发 4 次」改成 0.4ATR 后恢复到 90 次，这个修复是对的。**结论：保留，优先 4h。**

### 3.2 只配当提示（不能当入场依据）
- **摆动点/箱体突破（4h）**：净 +8.8bp，但多空分裂到极致（多 +10.9 / 空 -16.5，空 t=-2.16），
  bootstrap [-19, +54]。方向上更像「这段行情里只做多能活」，不是稳定结构。1h 已 exclude，正确。
- **连续同向 K 线**：neutral，永远不开仓，超额 ≈0；作为「别追」的提醒可以，别进策略胜率统计。
- **波动率异常**：关闭中，且 direction=neutral，开了也只能提示。

### 3.3 确定性亏钱 / 结构性失效
- **回归通道（4h）**：净 -35.8bp，bootstrap 上限 -1、P(>0) 仅 2%，1h 也是 -8.5bp。
  这是唯一「统计上能确定是负的」指标。它的问题在入场时点：h1 -12.8 → h6 -27.8，越拿越亏。
  与第 15 节「反向也不显著」一致：**不是反向信号，是噪音 + 追高**。建议 4h 不再进自动开仓白名单。
- **订单块（Lux/Flux）**：180 天 8 币 **零信号**。原因不是行情，是逻辑：
  ① `find_*_order_blocks` 只返回**最后一个**仍然有效的 OB；
  ② `_check_ob_base` 要求 `prev.close < bottom` 且 `current.close > top`，即**一根 K 线跨越整个区间**才报突破。
  两者叠加，条件近乎不可能同时满足。它现在只消耗 CPU 和配置认知，不产生信息。
- **SMA 25/99（ma_breakout）**：不算「失效」但**过量且方向错位**。1h 上占 76% 的信号量（3.22 条/币/日），
  4h 上占 50%，h1 超额 -9.0bp、t=-2.78（多 -8.0 / 空 -10.1 双双为负）。
  它的问题也是时点：突破当根收盘入场，下一根就回吐 → 典型「在突破 K 线顶部成交」。
  按当前密度，若扫描扩到 Top100，仅这一个指标在 1h 上就是 ~320 条/天的推送量。

### 3.4 未知（不能算「没用」，只是没验证过）
- **KDJ（9/3/3）**：关闭，且从未进入回放过，无任何样本。
- **1d 周期**：`signal_config` 里给了 1d 的 overrides（level 10/10、TCB 150 根），
  但 `signal_scan_timeframes` 只有 `['1h','4h']`，1d 参数是死配置，也从未回测。

## 4. 五个跨指标的工程问题

1. **ATR 有三套口径**：`strategies` 用 `pandas_ta.atr`（Wilder RMA），
   `protection.engine._atr_from_df` 和 `signals.outcomes.to_frame` 用 TR 的简单均值。
   所以「入场过滤用的 ATR」和「止损用的 1.5×ATR」不是同一个数，跨周期会差 5~15%。
   这不会让策略失效，但会让「1.5 ATR」这个参数无法复现、也无法跨模块对齐。
2. **ema_cross 的多空判定不对称**（`strategies.py:455-456`）：
   多头要 `prev.close < prev.ema`，空头要 `prev.low > prev.ema`（整根 K 线在 EMA 上方）。
   空头条件更严 → 1h 空头只有 106 笔却 +19.6bp，多头 266 笔 +0.6bp。
   要么这是「更干净的破位」的隐性优势，要么是个 bug，**必须显式决定**，否则这条 edge 不可复现。
3. **量能门槛已降级但仍留在配置里**：`volume_filter_mode='record'` 让 `volume_confirm` 永不生效，
   而 `signal_config.json` 里还有 **8 处** `volume_confirm: true` + 倍数。这是死配置，会误导后来的人
   （改动 `volume_confirm` 完全不改变行为）。建议删掉或加注释指向 `volume_filter_mode`。
4. **8 个策略都包在 `try/except` 里只打一行 error**：任一指标抛异常就静默失效，
   和订单块「0 信号」在表面上完全一样，无法区分「没机会」和「坏了」。
   建议给每个策略加「最近一次成功计算时间 + 异常计数」的运行时指标。
5. **共振确认没有增量**：1h 独占 -0.4bp（4479 笔）vs 共振 +6.9bp（541 笔）；
   4h 独占 -8.0bp vs 共振 -4.4bp。`families.py` 按族去重是对的（防重复计数），
   但「多策略共振=更强」这个假设在数据上得不到支持，`signal_auto_trade_confirmations` 不要超过 1 来当过滤器用。

## 5. 建议动作（按 ROI）

**P0 — 立刻改，零成本**
1. `trend_channel_breakout` 移出 `signal_auto_trade_strategies`（4h 净 -35.8bp，唯一确定性为负）。
2. 订单块二选一：改成「价格接近/回踩区间即提示」（`alert_on_rejection` + 区间距离阈值），
   或直接 `enabled: false`。保持现状是最差的选项。
3. 统一 ATR 实现：抽一个函数（建议 RMA），`protection`、`outcomes`、`strategies` 全用它。
4. 清理死配置：`volume_confirm` 系列字段、1d 的 overrides、`kdj_cross`（或补上回放）。

**P1 — 需要样本外验证，别直接上仓位**
5. RSI 背离（4h）单独跑到 30 币 / 12 个月，做时间切分验证；只有 OOS 仍为正才谈实盘。
6. `ema_cross` 的多空条件统一后重跑一次，确认 1h 空头的 +19.6bp 是条件不对称造成的还是行情造成的。
7. `ma_breakout` 改入场方式（突破后回踩 N 根再入）再测同一份数据，验证「-9bp」是否只是时点问题。

**P2 — 工程与可观测性**
8. 信号页的 `forward_stats` 增加「扣成本后」列和每币分档，避免再出现「看着正、扣成本归零」。
9. 给每个指标加运行健康度（最近成功时间 / 异常次数 / 今日信号数），把「静默死亡」变成可见。
10. 推送限流：同币同周期同族信号在 N 根 K 线内只推一次，先压住 1h 上 3.2 条/币/日的量。

## 6. 这份审计说不了什么

- 只有 180 天、8 个币、1h/4h 两个周期；**没有样本外**，也没有跨行情段（单边上涨 + 单边下跌）的验证。
- 超额只扣了 8bp 往返成本，没建模滑点、资金费率、停牌与流动性。
- t 值未做重叠信号校正（相邻信号高度相关），显著性以 bootstrap 区间和量级为准。
- 订单块的「0 信号」是从回放表反推的，**没有单独跑一次带日志的回放确认它是否抛异常**；
  两种可能（条件过严 / 代码异常）都会得到 0 行，需要用 P0-2 的改动顺便验证。
- 本审计不含 PandaAI 平台实跑、不做因子挖掘、不消耗任何算力预算。
