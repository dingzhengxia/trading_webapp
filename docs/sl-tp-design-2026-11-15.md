# 止损 / 止盈模型定稿（2026-11-15）

> 本文是仓位保护 v2 决策层的**唯一口径**。`backend/app/protection/risk_model.py`
> 里的每条分支都必须能在这里找到出处；参数语义与默认值也以本文为准。

## 0. 为什么重做

旧模型有「风险周期」这个概念：一旦识别到加仓就整行重建状态
（`new_state`），已触发档位、峰值、止损价、初始仓位全部归零。由此引出的
故障不是三个 bug，而是同一个结构性缺陷的三种表现：

| 现象 | 直接原因 |
|---|---|
| ETH 兜底 STOP 落在真实开仓价**之下** | 加仓后均价上移，计划仍按旧均价算 `T4 − 1.5ATR` |
| 同一段行情卖两次 / 一档都卖不出 | 重建时 `tier_done` / `tp_done` 被重置或原样继承 |
| BTC 标称减 25%、实际砍掉剩余 79% | 比例分母是过期的「周期初始仓位」 |
| BTC 灾难线 −11.3%，比任何结构位都远 | 灾难线由 `T4` 外推 1.5 ATR，而不是风险预算 |
| 0.5R 保本 → 立刻被扫 → 行情继续走 | 保本触发按 R 计，R 由结构决定、与波动尺度脱钩 |

所以这次不是调参，是把模型换成**单状态机**：没有「重建」，只有状态转移。

## 1. 四条不变量

1. **仓位真值只有交易所的 `(q, E)`**。账本只记「不变量」和「历史动作」，
   不记「应该有多少仓位」。每轮以交易所为准刷新，不做增量推算。
2. **分批比例的分母是「规模锚 S = 历史最大持仓量」，只增不减。**
   - 人工减仓 → `q` 变小，`S` 不缩 → 不会出现「按旧仓位比例一刀清零」；
   - 人工加仓 → `S` 抬到新 `q` → 新仓位自动纳入后续批次。
3. **止盈按 R、止损按 ATR。**
   - `R`（以及由它算出的 TP 价）在建计划时**冻结**，否则止盈线会跟着行情跑，永远到不了；
   - 止损阶梯全部用 ATR 归一——ATR 是「正常波动尺度」，跨币可比；
     `R` 由结构位决定，BTC 的 R 可以到 6%，用它做保本触发等于把止损从 −6% 一步跳到成本价。
4. **止损只朝盈利方向移动，没有加仓例外**。每笔开仓（lot）在本地有独立的
   成交价、四档、R/TP 阶梯、峰值与止损：加仓只新建另一个 lot，老 lot 的计划和
   进度一字不动；减仓按比例分摊到各 lot，价格不变、数量同比缩小。
   交易所层面同币种同方向的仓位仍会被币安按均价合并，但那只是 `(q, E)` 事实，
   不是我们计算止盈止损的基准。系统只保留 v2 这一条止盈止损链路。

## 2. 风险几何（`build_plan`）

全部用「相对持仓均价的距离 `d`」运算（正数 = 亏损方向），多空对称：

```
atr_pct = atr / E
d_min   = max(risk_min_pct, 0.8 × atr_pct)          # T1 最近：低于 0.8 ATR 就在噪声里
d_max   = max(risk_max_pct, 1.5 × d_min)            # 灾难线 = 单笔最大亏损
d_t1_far= clamp(t1_max_pct, d_min, 0.85 × d_max)    # T1 最远

T1 = clamp(结构低点距离 + 0.5×ATR, d_min, d_t1_far)
T2/T3/T4 = T1 + (d_max − T1) × 25% / 50% / 75%
灾难线 = d_max
R = |E − T1|； TP_k = E ± R × tp_r_multiples[k]
```

要点：

- **只有 T1 依赖结构位。** 结构位回答「这单什么时候算错了」；T2~T4 是
  「亏损预算怎么分段消耗」。这样四档永远落在预算内、永远严格单调，
  不会因为某个周期的结构位特别远就把最后一档顶到 −8%、−11%。
- **灾难线 = 单笔最大亏损**，不再由 T4 外推。旧口径 `T4 − 1.5ATR` 会把
  BTC 的兜底推到 −11.3%，比任何一个结构位都远，等于「兜底」比「止损」还晚触发。
- **`t1_max_pct` 是结构位的封顶**：刚暴跌完的低点可能离均价 6~8%，
  直接把 T1 放过去就是一笔亏 8%；结构位比封顶更近时仍以结构位为准。

实测（默认参数 `risk_min_pct=1.5% / t1_max_pct=4% / risk_max_pct=6%`）：

| 标的 | ATR(2h) | T1 | T2 / T3 / T4 | 灾难线 |
|---|---|---|---|---|
| BTC 65,391 | 1.87% | −3.83% | −4.37 / −4.91 / −5.46% | **−6.00%**（旧：−11.29%） |
| ETH 1,804.8 | 1.55% | −3.26% | −3.95 / −4.63 / −5.32% | −6.00% |
| 高波动 ATR 6% | 6.0% | −4.80% | −5.40 / −6.00 / −6.60% | −7.20%（0.8ATR 抬升下限） |

## 3. 减仓量：只有一处口径（`sell_qty`）

```
卖出量 = min(S × 档位比例, 当前持仓 × (1 − 保留比例))
```

- 结构档：`保留比例` = 0（T4，结构彻底失效，允许清仓）/ 10%（T1~T3，给后面留尾巴）；
- 止盈档：`保留比例` = `tp_keep_ratio`（默认 25%，留给追踪）。

`min` 的第二项是硬保险：人工减仓后 `q` 变小，最多卖到保留线，永远不会一刀清零；
人工加仓后 `S` 抬升，后续档位按新规模分批。

## 4. 止损阶梯（`_stop_action`）

候选全部按 ATR 归一，多单取最大值、空单取最小值：

| 层 | 触发条件 | 价位 |
|---|---|---|
| L0 灾难 | 永远 | `d_max`（单笔最大亏损） |
| L1 破位推进 | 第 i 档已触发 | `T(i+1)`（i=3 时取 T4） |
| L2 保本 | 浮盈 ≥ `breakeven_trigger_atr`×ATR（2） | `E ± max(0.1%, 0.4×ATR)` |
| L3 锁利 | 第 i 档止盈已成交 | `TP_i ± 0.1%` |
| L4 追踪 | 浮盈 ≥ `trailing_start_atr`×ATR（2.5） | `峰值 ∓ 1.5×ATR` |

两个硬夹子：

- **离现价至少 `max(0.6×ATR, 0.3%)`** —— 旧值只有 0.2% 价格，
  BTC 的 1 ATR 就有 1.87%，等于把止损放在噪声里，一个 tick 就打掉；
- **变化幅度小于 `max(0.15%, 0.15×ATR)` 时不折腾交易所**（防撤单重挂刷请求）。

无加仓例外：`snap.rebased` 仅为旧字段，永远为 `False`。新加仓是独立 lot，
用自己的成交价建自己的四档与止损；老 lot 的止损不会因为均价变化而下移。

## 5. 人工干预识别（`detect_intervention`）

只看两个交易所事实，不猜：

1. **持仓均价变了 → 一定加过仓。** 币安按平均成本法，减仓不改变 `entryPrice`，
   只有增加仓位才会让它移动。这条比「比较初始仓位」可靠得多：减仓后再加仓回补到
   初始仓位以下的场景（ETH 0.112 → 0.333，base 0.733）旧逻辑完全看不见。
2. **数量变了（均价没变）→ 加/减仓。**

加仓时反解本笔成交价：`p = (E_new×q_new − E_prev×q_prev) / Δq`。
`Δq=0`（加在均价上）时均价不动，只靠数量判定。

响应：

| 事件 | 计划 | 进度 | 止损 | 通知 |
|---|---|---|---|---|
| 加仓 | 用反解出的本笔成交价新建一个独立 lot 计划；老 lot 完全不动 | 各自独立，互不继承 | 各笔只按自己的基准上移 | 推送 |
| 减仓 | 各 lot 价格不动，数量按当前持仓比例分摊、规模锚同比缩小 | 不动 | 不动 | 幅度 ≥10% 才推送 |
| 全平重开 | 新建 | 新建 | 新建 | 台账 |

`_apply_reduce` 成交后会立刻把 `q_seen` 同步成新数量——否则下一轮会把我们自己
的减仓误判成「人工减仓」。

## 6. 止盈：「先突破、再回落」

- 不在交易所预挂止盈单。挂上去等于把判断权交给撮合：插针碰到 TP 就成交，
  后面走出的大行情一点吃不到。
- 引擎 3 秒一轮：`peak ≥ TP×(1+突破确认)` 才登记 `tp_armed`；
  之后价格回到 TP（多单 `price ≤ TP`）才卖，一次只卖一档，从高档往低档扫。
- `tp_armed` 是 sticky 状态，只在加仓重基准时清空。

## 7. 结构重估（`replan_plan`）—— 只动 T1 以外的部分

- 已触发档位冻结；未触发档位只许外移；灾难线只许外移；
- `entry` / `risk` / `tp_prices` / `tp_ratios` 终身锁定；
- T1 一旦触发，整条阶梯锚定（T2~T4 是 `T1 → 灾难线` 的等分），不会再动；
- 幂等：同一组输入连续重估两次，第二次必须返回 `None`。

## 9. 已知取舍

- **止盈「回落才卖」必然走 taker**（约 0.04%）。这是「不在交易所预挂」的固有权衡：
  要判断突破回落，就不能让撮合先成交。
- **波动极大时四档会被压缩**：`risk_max_pct` 是硬上限，ATR 6% 时
  `0.8ATR = 4.8%` 已经逼近 6% 预算，四档只能挤在 1.8% 区间里。
  这是「亏损上限优先于档位间距」的有意选择——高波动下快速清仓比精细分批更重要。
- **加仓不继承任何进度**：新 lot 从 TP1/T1 重新开始，老 lot 已卖过的档仍算完成。
  同一时刻可能有多笔各自的阶梯在跑；这是「每笔独立计算」的必然结果。
- **交易所 STOP 按 lot 数量挂**：单笔触发只减该笔仓位，不会连带平掉其它笔。
