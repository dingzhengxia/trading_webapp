# 信号策略有效性验证报告

- 生成时间：2026-11-12
- 代码基线：`master @ eb144a4`（signal_config v2）
- 数据集：Binance 现货 K 线，BTC/ETH/SOL/BNB
  - 1h：3000 根（2026-07-10 → 2026-11-12，约 125 天），有效样本 1500 根/币
  - 4h：1200 根（2026-04-26 → 2026-11-12，约 200 天），有效样本 1000 根/币
- 方法：**用生产策略代码逐根回放**（`tools/strategy_probe/`），信号当根收盘产生、下一根开盘入场，
  统计 1/4/12 根（4h 为 1/3/6 根）后的收益，并减去「同时段同方向的平均漂移」得到超额（excess）。

## 0. 一句话结论

**当前这套是合格的信息提示系统，不是有正期望的交易系统。** 1h 上「关键位突破」在统计上显著亏钱
（持有 4 根平均 -31bp，t=-3.3，N=155），其余策略扣掉成本后在 0 附近；唯一像样的正结果（4h 关键位
做多 +97bp）样本只有 40 笔、单一时段，不足以支撑自动开仓。

## 2. 五个发现

### 发现 1：所有信号都呈「均值回归」特征，越拿越亏

1h `level_breakout`：持有 1 根 -1bp → 4 根 **-31bp** → 12 根 **-43bp**，单调恶化。
`trend_channel` 12 根 -39bp（t=-2.7）。说明信号在**冲动 K 线收盘后才确认**，入场时行情已走完，
后续 4–12 根回吐——典型「追高/追空」而不是「突破跟进」。

### 发现 2：`level_breakout` 在 1h 上是净损耗，且多空都亏

多 -32bp / 空 -31bp，两个方向同时为负，这不是运气问题，是逻辑问题：7/7 摆动点的「前高前低」
在 1h 上属于微观结构，突破后大概率回来。同一个策略在 4h 上做多 +97bp、做空 -55bp，
方向完全相反——更像是这个时段 4h 结构恰好有效，而不是策略稳定。

### 发现 3：`ema_cross` 实际上已经死了

125 天、4 个主流币、1h 只触发 **34 次**（约 0.07 次/币/天），4h 只有 **4 次**。
原因是 EMA120 + 1.0 ATR 缓冲 + 2.0x 量能三重叠加。它现在既提供不了信息，也提供不了交易，
不如显式决定：要么把缓冲降到 0.3–0.5 ATR，要么从白名单删掉。

### 发现 4：量能确认没有筛选价值

同样配置下把 `volume_confirm` 关掉：

| 策略 | 信号数 | 1h h4 超额 |
|---|---|---|
| `ma_breakout` 开启 2.0x 量能 | 98 | -1bp |
| `ma_breakout` 关闭量能 | 729 | **+9bp** |
| `level_breakout` 开启 1.5x | 155 | -31bp |
| `level_breakout` 关闭 | 225 | -21bp |

量能门槛砍掉了 70–85% 的信号，但没有让剩下的更准，反而在 `ma_breakout` 上砍掉了赚钱的那批。
量能更适合当**统计字段**（记录、分档复盘），而不是**硬门**。

### 发现 5：加「趋势过滤」不是万能药，两个周期结论相反

以收盘价 vs 同周期 EMA200 判定顺势/逆势：

| 周期 | 做多·顺势 | 做多·逆势 | 做空·顺势 | 做空·逆势 |
|---|---|---|---|---|
| 1h (h=4) | **-52bp** | -15bp | +1bp | +9bp |
| 4h (h=3) | **+39bp** | -47bp | -38bp | **+39bp** |

1h 顺势做多更差、4h 顺势做多更好——两个周期方向相反。此时硬加统一趋势过滤，只能在样本内
拟合出「1h 反着做、4h 顺着做」这种不可外推的结论。

## 4. 这套数据说明不了什么（必须一并读）

- **只有 4 个主流币**，你的扫描池是 31 个（含小币）；小币波动结构完全不同，结论不可直接迁移。
- **用的是现货 K 线**（本机只能连 `data-api.binance.vision`），永续有资金费率与不同流动性。
- **单一市场状态**：125/200 天，恰好是震荡偏弱的一段；趋势市里突破类策略的表现会完全不同。
- **N 偏小**：单格 14–96 笔，t 值 1.5–2.5 的格子经多重检验后大多不显著，只有 |t|>3 的负结论较硬。
- **测的是固定持有期**，没有复现系统的 SL/TP 与 post-only 成交；真实结果会因止损被打断而不同。
- 未计资金费率、滑点、爆仓风险。

4. 1h 扣成本后仍然全为负（最好的 `ma_breakout` 也就 -1bp），**1h 依旧不具备交易价值**，

## 7. 扩大样本复测 + 逻辑实验（2026-11-12 第二轮）

上一轮只有 4 币、125/200 天，被质疑样本太小。这一轮扩到 **8 币 × 1h 4000 根（166 天）
× 4h 1500 根（250 天）**，共 **25 782 条方向性信号**，并把「逻辑」本身做成可验证实验：
入场延迟、持有期长度、反向跟随、ATR 止损止盈。

口径：超额 = 单笔收益 − 同币同周期同偏移同持有期的**无条件漂移均值**（不奖励牛市做多），
成本按往返 8bp。

### 7.1 入场延迟（延迟 0 = 现在线上行为）

| 周期 | 延迟 0 根 | 延迟 1 根 | 延迟 2 根 |
|---|---|---|---|
| 1h（持有 4） | -0.6bp（t=-0.6） | -2.4bp（t=-2.4） | -3.8bp（t=-4.2） |
| 4h（持有 3） | -0.1bp（t=-0.1） | **+26.1bp（t=+10.0）** | +10.5bp（t=+3.9） |

4h 这个 +26bp 看着像金矿，做了四道稳健性检查：

| 检查 | 结果 |
|---|---|
| 分币 | 8/8 币为正（+4 ~ +60bp） |
| 分月 | 7/8 月为正（2026-05 为 -18.6bp） |
| 前后半段 | +17.5bp / +36.3bp |
| 聚类 t（按币×日聚合，消除同 bar 重叠） | +4.3 |
| 控时段漂移（同小时基准） | +26.3bp，未变 |
| 去掉同 bar 重复信号 | +22.8bp |

**但一换出场规则就打折**：把「持有 3 根」换成 ATR 止损/止盈（更接近真实交易）：

| 4h 入场 | SL1.5ATR / TP2R | SL1.5ATR / TP3R | SL2ATR / TP2R |
|---|---|---|---|
| 立即入场 | +5.8bp（净 -2.2） | +6.6bp（净 -1.4） | +5.0bp（净 -3.0） |
| 延迟 1 根 | **+12.6bp（净 +4.6）** | **+13.2bp（净 +5.2）** | +8.5bp（净 +0.5） |

也就是说：+18bp 的净利润里，有大约 13bp 依赖「必须在第 5 根 K 线**精确**离场」——
固定持有 h=3 为 -0.1bp、h=4 为 +18.6bp、h=6 为 -2.3bp，曲线是尖峰不是平台。
配上止损止盈后只剩 **+5bp 净、胜率 45.5%**，属于「不能上实盘、但值得纸面跟踪」的级别。

### 7.2 其余实验

| 实验 | 结果 | 读法 |
|---|---|---|
| 持有期扫描（1h h=1..12） | 最好 h=2 +2.1bp（净 -5.9） | 全部扣成本为负，1h 无可用边际 |
| 持有期扫描（4h h=1..6） | h=4 +18.6bp，相邻 h 均为负 | 尖峰结构，见上 |
| 反向跟随（fade） | 1h +0.6bp / 4h +0.1bp | 不是「方向做反了」，是**没有信息** |
| ATR 止损止盈（立即入场，4h） | 全部净 -1.4 ~ -3.0bp | 出场改造救不了入场质量 |

### 7.3 结论

1. **不要再改信号判定逻辑**（指标参数、量能、趋势过滤都试过了，没有一样能稳定转正）。
2. **1h 确认无交易价值**：8 币 166 天，任何持有期扣成本都是负的，只适合当提示看。
3. **4h「T+1 入场」是这套系统里唯一像样的边际**，但它依赖精确的离场时点，
   配上止损止盈只剩 +5bp 净 —— 值得**纸面跟踪 4–6 周**，不值得直接上实盘。
4. **真正的结构性缺口是出场层**：`auto_trader.py` 只有开仓、没有止损/止盈/时间止损，
   导致任何入场质量都无法落地，也无法度量。要做自动开仓，这是必须先补的。
5. **没有前视记录就没有反馈闭环**（P6 仍未做）：上面所有数字都来自离线回放，
   线上真实滑点、成交、跳空都会再打折。

复现：`tools/strategy_probe/` 下 `fetch2.py` → `run_wide.py` → `logic_test.py` →
`robust.py` / `robust2.py` / `robust3.py` / `robust4.py`。

## 8. 落地：纸面跟踪 + 前视收益（P6 / P2 的替代方案）

上一轮的结论是「不要改信号判定，缺的是出场层和反馈闭环」。这一轮把两块补上了。

### 8.1 结构

```text
扫描 -> emit_signal -> 队列 -> SignalDispatcher.dispatch_batch
                                ├─ store.add（展示，全量）
                                ├─ 钉钉推送（量能门槛）
                                ├─ OutcomeTracker.on_signal   ← 新增：复用同一条过滤链
                                └─ SignalAutoTrader（真实开仓，默认关）

OutcomeTracker（独立 300s 循环，按 (币种, 周期) 聚合后只请求一次 K 线）
  ├─ 前视收益：每条方向性信号记录 T+4 / T+12 收益
  └─ 纸面持仓：开仓 -> ATR 止损 / R 倍数止盈 / 超时平仓 -> 落库统计
```

**关键点：纸面跟踪没有另写一套过滤逻辑**，而是复用了 `SignalAutoTrader` 的整条链
（开关 / 方向 / 策略 / 周期 / 确认族数 / 冷却 / 持仓上限），只把「下单」换成「记录」，
冷却状态用独立的 `signal_state.paper_state` 键，与真实开仓互不干扰。因此：纸面结果
≈ 打开自动开仓后的行为，但永远不碰交易所。

### 8.2 出场规则（`signals/outcomes.py`）

- 入场价 = 信号价（扫描时记录的收盘价），检查从**下一根 K 线**开始（信号 bar 已收线）；
- 止损 = 入场 ∓ `sl_atr × ATR(14)`；止盈 = 入场 ± `tp_r × 止损距离`；
- 同一根内止损与止盈都触发 → **止损优先**（保守，不让回测偏乐观）；
- 跳空越过触发价 → 按**开盘价**成交，不按理论价；
- 超过 `max_bars` 根仍未触发 → 按收盘价超时平仓；
- 窗口没走满且未触发 → 本轮不判定（避免半路误判超时），等下一轮。

### 8.3 配置项（都能在信号页改，落 SQLite）

| 键 | 默认 | 说明 |
|---|---|---|
| `signal_paper_enabled` | false | 纸面跟踪总开关 |
| `signal_paper_sl_atr` | 1.5 | 止损 = N × ATR(14) |
| `signal_paper_tp_r` | 2.0 | 止盈 = N × 止损距离 |
| `signal_paper_max_bars` | 6 | 最多持有根数（超时平仓） |
| `signal_forward_bars` | [4, 12] | 前视收益的持有期 |

纸面仓位名义价值复用 `signal_auto_trade_value_usd`；方向/策略/周期/确认数/冷却/持仓上限
全部复用 `signal_auto_trade_*`，避免出现两套"看起来一样但值不同"的参数。

### 8.4 怎么看

- **信号列表新增「前视」列**：`T+4 +0.83% / T+12 -1.2%`，红绿按涨跌（用户口径：红跌绿涨）；
- **信号页新增「纸面跟踪与结果」卡片**：未平仓明细（入场/止损/止盈）、已平仓统计
  （样本、胜率、均收益、累计、均持有根数、出场原因分布）、按周期×策略的前视收益汇总；
- 数据落 `signal_state` 表（`paper_positions` / `paper_trades` / `signal_forward_results`），
  重启不丢。回填窗口 300 根 K 线，更老的信号不补。

### 8.5 已知限制

1. 只模拟价格，**不含手续费、滑点、资金费率**（8bp 往返成本要自己在看数时扣）；
2. 用的是 K 线高低点判定触发，真实成交仍可能有偏差（尤其小币插针）；
3. 冷却是按信号时间戳算，不是按真实成交，纸面笔数会略多于实盘；
4. 前视收益是统计口径（每币每信号一条），不是组合净值，不能直接当收益曲线看。

### 8.6 建议的观察节奏

先跑 **4–6 周**，每周看一次「按周期×策略」的 T+4/T+12：样本 <30 不看结论；
某个策略在 4h 上连续两周 T+4 为正且胜率 >50%，再考虑把它加进自动开仓白名单。
1h 的所有策略在这套统计里预计仍是负的——如果真是这样，就把它彻底当提示用。

## 9. 收益回测：出场口径 × 实盘杠杆（2026-11-12 第三轮）

前八节都是**单笔统计**（超额 bp、t 值）。这一节换成**账户视角**：资金曲线、年化、最大回撤、盈亏比、月/币胜率——即"这套出场规则真跑起来赚不赚钱、中途要扛多大回撤"。

### 9.1 先说清楚"合并"合并了什么

| | 这次合并的 | 没有动的 |
|---|---|---|
| 位置 | `app/core/exit_rules.py`（新建） | `app/protection/`（1996 行风控引擎） |
| 内容 | 设置页的 `{side}_stop_loss_percentage` / `{side}_take_profit_percentage` ÷ `leverage` 折算成价格距离 | ATR 止损、EMA 结构止损、程序化 `STOP_MARKET` 条件单、移动止盈、algo 状态机 |
| 调用方 | 实盘挂单 `sl_tp_logic_async` + 纸面跟踪 `tracker`，**同一份代码** | 独立子系统，仍按自己的逻辑跑 |

之所以现在只合并这一层：`app/protection/` 是**交易所侧条件单**体系（下单/查单/撤单/状态机），
它管的是"仓位已经开着的时候怎么保命"，不是"信号该在什么价格离场"。
两者要做成一套，得先定边界（谁负责挂单、谁负责判定、冲突时听谁），不是一次重构能收口的。

### 9.2 回测口径

- **组合视角**：同一币在持仓期间**不重复开新仓**（= `auto_trader` 的真实约束），
  避免同一段行情被多个信号重复计数；
- 每笔名义仓位 = 净值的 10%（8 币并发最多占 80%）；收益按**出场时间**逐笔复利；
- 成本 8bp 往返；入场 = 信号后第 2 根开盘（即"等一根"，第 7 节已验证这是唯一有 alpha 的入场）；
- 输出两套：**1x 现货口径**（看策略本身）+ **实盘杠杆口径**（每笔 10% 保证金 × L 倍，单笔亏损封顶于保证金 = 爆仓）。

脚本：`tools/strategy_probe/exit_pnl.py`（收益）、`exit_sweep.py`（参数扫描）。两者都调用 `exit_modes.collect()`，
出场判定走的是**生产代码** `core.exit_rules` + `signals.outcomes`，不是另写一份。样本：8 币 × 4h 250 天 / 1h 166 天。

### 9.3 4h · 等一根入场 · 最大持有 6 根（8 个月）

| 口径 | 笔数 | 总收益 | 年化 | 最大回撤 | Sharpe | 盈亏比 | 月胜率 | 币胜率 |
|---|---|---|---|---|---|---|---|---|
| A 实盘现设（-15% / +30%） | 845 | +4.8% | +10.0% | -12.5% | 0.77 | 1.05 | 43% | 50% |
| B 收紧（-2.5% / +5%，空 -4% / +7.5%） | 1132 | +12.8% | +27.8% | -17.0% | 1.81 | 1.10 | 57% | 62% |
| C ATR 1.5 / 2R | 1363 | -3.7% | -7.3% | -20.6% | -0.46 | 0.98 | 43% | 50% |
| **D 纯超时（不挂价格单）** | 838 | **+12.2%** | +26.5% | **-11.1%** | **1.87** | **1.14** | 57% | **75%** |

1h 四个口径全负（A -11.6%、B -10.8%、C -39.8%、D -11.1%，均为 8 个月总收益）——**1h 没有任何出场规则能救**。

### 9.4 三个硬发现

**(1) 实盘的 -15% / +30% 等于没有出场层，而且是最差的一种"没有"。**
`leverage=20, long_stop_loss=300%` → `300/100/20 = 15%` 价格距离。4h 上 845 笔里只触发 **15 次止损、0 次止盈**，
其余 830 笔全是超时平仓。而这 15 次每一次都是"小亏拖成大亏"：同样的信号，D（不挂单）赚 +12.2%，
A（-15% 兜底）只赚 +4.8%，**净损失 7.4 个百分点**；按币看 ADA 从 +39.9% 掉到 -8.2%。
保险买得太贵、而且只在深亏时才赔。

**(2) 止损越紧越差，没有一个宽度能救。**

| 止损价格距离 | 2% | 3% | 4% | 6% | 8% | 10% | 15% |
|---|---|---|---|---|---|---|---|
| 8 个月总收益 | -27.6% | -22.6% | -15.2% | -3.7% | +4.5% | +2.2% | +12.2% |
| 触发止损次数 | 623 | 352 | 194 | 67 | 29 | 19 | 0 |

ATR 口径同理：2ATR -10.1%、3ATR +1.7%、4ATR -0.4%，全都劣于不挂单。原因在**收益结构**：
这批信号的超额集中在"持满 6 根"这一段路径上，任何中途的强制离场都在截断右尾，
而左尾并没有被真正省下来（止损后立刻重开下一笔，交易频率反而上升：838 → 1363 笔）。

**(3) 但"不挂单"的结论不稳健，参数非常脆。**

| 最大持有 | 4 根 | 5 根 | 6 根 | 7 根 | 8 根 |
|---|---|---|---|---|---|
| 总收益 | -6.9% | -21.1% | **+12.2%** | -9.0% | +2.6% |

一个参数上下挪一根，收益就从 +12% 掉到 -9%。这说明 6 根是**在这段样本里拟合出来的峰值**，
不是市场的结构性规律。样本只有 8 个月（4h）、5.5 个月（1h），没有跨牛熊，不宜当作稳定边际。

### 9.5 实盘杠杆口径：20x 是这套信号的死因

每笔固定 10% 保证金、单笔亏损封顶于保证金（即爆仓），收益线性累加（爆仓后不能复利）：

| 4h 口径 | 1x | 5x | 10x | 20x |
|---|---|---|---|---|
| A 实盘现设 | +5% / -11% | +26% / -36% | +53% / -50% / 15 爆 | +317% / **-97%** / 38 爆 |
| B 收紧 | +13% / -14% | +63% / -36% | +125% / -52% | +250% / **-101%** |
| D 纯超时 | +12% / -10% | +60% / -28% | +123% / -50% / 3 爆 | +369% / **-97%** / 33 爆 |

- 20x 下"总收益 +317%"没有意义：**最大回撤 -97%，中间爆仓 38 次**，任何真实账户都撑不到最后；
- 1h 更直接：10x 就 -120%、20x 是 -162%，等于归零；
- 名义仓位敏感性（4h·D·现货）：10% 名义 +12%/-11%、25% 名义 +31%/-26%、50% 名义 +64%/-45%、100% 名义 +119%/-71%——
  **收益和回撤是等比例放大的**，加杠杆不产生额外期望，只提前撞上回撤上限。

### 9.6 结论与建议参数

1. **出场层不给收益加分，只决定你要不要为尾部买保险。** 想赚满这批信号的收益，就得裸持到超时；想有兜底，
   就得接受收益腰斩（-6% 止损：+12.2% → -3.7%）。这是取舍，不是 bug。
2. **当前 `-15% / +30%` 是最坏组合**：平时不保护，触发时专砍深亏。至少改成 **-8% 止损 / 不设固定止盈**
   （等价 `stop_loss_percentage = 160`、`take_profit_percentage` 关掉或放到 500+），代价 +12.2% → +4.5%，回撤不变（-11.2%）。
3. **杠杆必须降。** 4h 这套信号在 10x 以内、每笔 10% 保证金是能活的（+123% / -50%）；20x 是数学上的必爆。
   建议 `leverage` 收到 **5x**，或保证金比例降到 2~3%。
4. **1h 建议直接停用（或只记录不下单）。** 任何出场、任何杠杆都是负的，含成本后最好 -10.8%。
5. **`signal_paper_sl_atr` 默认 1.5 偏紧**，纸面跟踪会系统性低估"裸持"的表现；建议默认改成 `max_bars=6` + `sl_atr=3.0`
   （纸面用于观测兜底版），或干脆 `enable_*_sl_tp=false` 只测纯超时，两套都在纸面上并跑对比。

> **复现**：`cd tools/strategy_probe && python exit_pnl.py`（收益表 + 曲线 + 稳定性）、`python exit_sweep.py`（出场参数扫描）。

## 11. 合并后的一轮回测：找到了一个真优化（2026-11-12 第五轮）

口径：完全走生产代码（`core.exit_rules` + `signals.outcomes`），4h 7656 条方向性信号、
8 币、180 天；入场取信号后第 2 根开盘；同币持仓期不重复开仓；往返 8bp；每笔名义 10% 净值。
脚本 `tools/strategy_probe/final_bt.py` + `validate2.py` + `robust5.py`。

### 11.1 先纠一个错：现行配置的回测结果是虚高的

`leverage=20` 时维持保证金约 0.5%，**爆仓线在价格反向 4.5–5%**。
而 `long_stop_loss_percentage=300 / 20 = 15%`——止损在爆仓线之外，永远到不了。

| 现行设置（4h 偏移2 6根） | 笔数 | 净/笔 | 总收益 | MDD |
|---|---|---|---|---|
| 回测口径（假装 -15% 止损能成交） | 838 | +14.2bp | +12.2% | -11% |
| **按 20x 爆仓线 4.6% 平仓（真实）** | 928 | **-18.6bp** | **-16.2%** | -23% |
| 按 20x 爆仓线 5.0% 平仓 | 908 | -14.8bp | -13.0% | -25% |

上一轮说"现行设置 +4.8%"是按"止损一定能成交"算的；实盘里那 800 多笔的真实结局是
**中途被强平**。这也是为什么实盘挂 3 倍保证金距离的止损等于没挂。

### 11.2 真正的优化：ATR 1.5 倍止损 + 止盈 1R

| 4h 偏移2 6根 | 笔数 | 净/笔 | 总收益 | MDD | Sharpe | 胜率 |
|---|---|---|---|---|---|---|
| 现行 percent -15%/+30% | 845 | +6.1bp | +4.8% | -12.5% | 0.77 | 47.5% |
| 纯超时（不挂价单） | 838 | +14.2bp | +12.2% | -11.1% | 1.87 | 47.7% |
| percent -8%（无止盈） | 849 | +5.7bp | +4.5% | -11.2% | 0.72 | 47.3% |
| **atr 1.5ATR / 1R** | **1931** | **+21.4bp** | **+50.5%** | **-14%** | **6.09** | **55.0%** |

**为什么是 1R 而不是 2R/3R**：放宽持有上限到 6/8/12/16/20 根，TP=1R 始终 +25~30bp，
TP=2R 始终 -3~-9bp，TP=3R 始终 -10~-22bp。这批信号是"走到约 1 倍风险距离就回头"的形态，
不是趋势启动点，**给 2R 以上的空间等于把已经到手的利润还回去**。

**参数是平台不是尖峰**（SL 1.0→2.0 全为正，TP 0.75R→1R 相邻值都强）：

| SL \ TP | 0.75R | 1.0R | 1.25R | 1.5R | 2.0R |
|---|---|---|---|---|---|
| 1.0ATR | +6.0bp | +5.2 | +4.4 | +3.8 | -8.8 |
| 1.25ATR | +14.9 | +12.9 | +10.3 | +0.5 | -7.0 |
| **1.5ATR** | **+19.8** | **+21.4** | +7.4 | +3.0 | -2.4 |
| 1.75ATR | +23.3 | +14.9 | +6.3 | +2.0 | +0.6 |
| 2.0ATR | +27.1 | +8.0 | +6.9 | -0.4 | -8.9 |

**不是单点拟合的另两条证据**：
- 持有 4/5/6/8/10/12 根，净收益 +18.2/+18.1/+24.8/+25.0/+27.6/+30.2bp——**全为正**，
  而纯超时是 -6.6/+14.2/+4.5/+31.8bp（上下跳）；参数不再是"6 根峰值"。
- 偏移 1/2/3 分别 +24.8/+21.4/+12.2bp，全为正。

### 11.3 样本内外与稳定性

| 检验 | 结果 |
|---|---|
| 前半 / 后半 | 前半 +12.4bp（t=1.9）/ 后半 **+30.5bp（t=4.0）** |
| 逐币 | 7/8 为正：SOL +40.5、XRP +44.8、DOGE +31.7、BNB +21.7、ADA +13.5、BTC +12.5、ETH +7.8、LINK -0.7 |
| 按月 | 5/7 为正；逐月均值 -46/+22/+40/-9/+42/+21/+58bp，**月聚类 t=1.39** |
| 成本敏感性 | 8bp→+21.4、16bp→+13.4、20bp→+9.4、30bp→-0.6（**滑点容错约 4 倍**） |
| 并发上限 | ≤2 时 +29.7bp/笔、MDD -13%；不限时 +21.4bp/笔、MDD -14% |

月聚类 t=1.39（7 个月）**不算统计显著**，这是这批样本的硬约束：只有半年，没跨牛熊。
但方向一致性强（两段、7/8 币、5/7 月、6 个持有期、4 倍成本带），比上一轮的"6 根 +12.2%"
（后半 -1.5%）扎实得多。

### 11.4 1h 仍然不值得做

用 1h 自身 ATR、偏移1、1.5ATR/1R：6/12/24 根分别 +3.5/+6.6/+7.9bp（总 +17%/+31%/+35%）。
但 4126 笔的换手下，16bp 成本就归零。**边际 6bp vs 8bp 成本，属于噪声**，维持"只推不下单"。

### 11.5 落地建议

| 配置 | 现在 | 建议 | 理由 |
|---|---|---|---|
| `leverage` | 20 | **5** | 只影响爆仓距离与占用保证金（下单名义额固定 = `signal_auto_trade_value_usd`）：20x 爆仓线 -4.6%，5x 约 -19.5%，止损才排得进爆仓线以内 |
| `signal_exit_mode` | percent | **atr** | 价格口径改用波动率，杠杆不再偷偷决定止损宽度 |
| `signal_paper_sl_atr` | 1.5 | 1.5 | 参数平台中心 |
| `signal_paper_tp_r` | 2.0 | **1.0** | 2R 以上全为负 |
| `signal_paper_max_bars` | 6 | 6 | 4~12 根都为正，取 6 最稳 |
| `signal_live_exit_timeout_enabled` | false | **true** | 19% 的交易靠超时退出，不开就没有这半边 |
| 1h 自动开仓 | 开 | 关 | 边际 6bp，扛不住滑点 |
| `trend_channel_breakout` | 在池 | 移出自动开仓 | 4h 单独看 -17.9bp/笔 |

**杠杆在这套系统里不等于收益倍数**：`auto_open_from_signal` 用的是 `value`（名义金额，默认
100 USDC），不是保证金，所以 20x→5x **不会改变每笔盈亏**，只改两件事：
① 占用保证金 100/L；② 爆仓线 ≈ 反向 1/L。

这正是问题所在——20x 的爆仓线（-4.6%）夹在 ATR 止损（价格 1.7–3.1%，高波动币到 4.5%）
和旧止损（-15%）之间：

| 杠杆 | 爆仓距离 | ATR 1.5 止损（中位 2.3%）占用保证金 | 结论 |
|---|---|---|---|
| 20x | -4.6% | 46%（高波动币 90%，一次插针即爆） | 不可用 |
| 10x | -9.5% | 23% | 勉强 |
| **5x** | **-19.5%** | **11.5%** | **推荐：止损排在爆仓线以内** |
| 3x | -32.8% | 7% | 更保守 |

**风险/笔（5x、名义 100 USDC）**：止损 2.3% × 名义 100 = 2.3 USDC ≈ 该笔保证金的 11.5%。
若账户 1000 USDC、并发 8 仓满仓，最坏情况同时止损约 -18.4 USDC = -1.8% 净值。

### 11.6 顺带修的实盘隐患

`signal_live_exit_timeframe` 是全局设置（默认 4h），而纸面跟踪用的是**信号自身周期**。
实盘若开 atr 口径、同时还有 1h 信号，会拿 4h 的 ATR 去挂 1h 的仓——止损宽一倍、单笔风险翻倍。
已改为：`auto_open_from_signal` 把信号周期透传为 `_signal_timeframe`，`_resolve_atr` 优先用它，
缺失或非法时才回退全局设置。新增测试 `test_resolve_atr_follows_signal_timeframe`，全量 **254 passed**。

## 12. 止盈止损还能再优化吗：动态出场全线落败（2026-11-12 第六轮）

问题：第 11 节的「atr 1.5 / 1R」是**静态**出场。实盘还支持 TRAILING_STOP_MARKET（回调率%），
超时执行器可以补保本与分批。逐一回测这些动态出场（脚本 `tools/strategy_probe/dynamic_exit.py`，
模拟语义与生产 `outcomes.simulate_exit` 一致：逐根先判触达再更新止损，杜绝根内前视）。

偏移1（立即入场）结果同构：静态 1.5/1R 仍最优（+24.8bp），全部动态出场更差。

### 12.2 为什么动态出场全败

1. **移动止损 / 回调率被 4h 波动绞杀**。1R ≈ 2.3% 的价格距离，4h 单根振幅中位数就在这个量级；
   移动止损在第一根大阳/大阴后立刻把止损抬进噪音区，被反向刺穿。回调率 1% 的 1917 笔里
   1886 笔以止损离场——止损变成了唯一的出场方式。
2. **保本止损丢掉了「被止损后继续拿满」的收益**。这批信号的超额集中在「持满 6 根」路径上
   （第 11 节已证），保本只是把右尾截得更早。
3. **分批止盈的最优变体（30%@1R + 余仓 TP2R）仍然 -9.4bp**，因为余仓的 2R 目标在第 11 节
   已被证明恒为负——分批救不了 2R，只是稀释了它。
4. 注：模拟里移动止损按根收盘更新，**比实盘连续跟踪更宽松**；实盘逐笔跟踪只会更差。

### 12.3 结论：出场层到此为止，别再优化它了

静态 `atr 1.5 / 1R / 6 根` 就是这批信号上的最优出场；所有「更聪明」的出场——移动、保本、
分批——都在截断这个策略唯一的盈利路径（走到 1R 就回头，或扛满持有期）。
`enable_{side}_trailing_stop` 保持关闭，不要开。

剩余优化空间不在出场层，而在三处：
1. **落地**：线上还在跑旧代码（见 11.7），参数没生效之前一切回测结论都是纸上收益；
2. **入场质量**：偏移1（立即入场）净 +24.8bp 高于偏移2 的 +21.4bp，且两段样本（+12.8/+37.0
   vs +12.4/+30.5）都为正、略优；等一根入场的历史优势在 ATR/1R 口径下不再必要。
3. **杠杆与并发**：5x 杠杆 + 并发上限（≤2 时 +29.7bp/笔）比任何出场规则省下的钱都多。

模拟器验证：基线复现第 5 轮结果（1931 笔 / +21.4bp / +50.5% / Sharpe 6.09，逐位一致）。

## 13. 手动与自动的统一止盈止损：从"开仓时挂一次"到"持续保证有止损"（2026-11-12 第七轮）

### 13.1 五种开仓入口已经是同一套

手动做多/做空/反手、自动交易任务、仓位再平衡、信号自动开仓、「同步所有止盈止损」按钮，
全部收敛到 `process_order_with_sl_tp_async → set_tp_sl_for_position_async → core.exit_rules`。
所以 `signal_exit_mode=atr` 一改，手动单与信号单同时改用 ATR 口径。

差异只有两处，都是刻意的：
1. **ATR 周期来源**：信号单跟随信号自身周期（`_signal_timeframe`）；手动单没有信号，
   回退全局 `signal_live_exit_timeframe`（默认 4h）。
2. **超时平仓只管自动仓**：`exit_executor` 只处理登记过的信号仓，手动仓永不被自动平掉。

### 13.2 真实缺口：挂单失败＝裸奔，只有按钮没有守护

开仓时 `set_tp_sl_for_position_async` 可能因为撤单失败、交易所拒绝、网络抖动而没挂上止损；
此前系统只会打一条错误日志，仓位就裸奔，直到用户手动点「同步所有止盈止损」。
这不叫"系统自动"。

### 13.3 落地：止损巡检（sltp_guard）

| 位置 | 改动 |
|---|---|
| `logic/sl_tp_logic_async.py` | 新增 `has_protective_order()`（只认 STOP/移动止损类，**止盈单不算保护**）、`ensure_positions_sltp_async()`（缺止损才补挂） |
| `signals/exit_executor.py` | 新增 `sltp_guard` 注入 + `guard_seconds`（默认 300s）节流；`tick()` 先巡检再对账/平仓，返回值加 `guarded` |
| `signals/service.py` | 装配 `_guard_sltp()`：共享交易所 + 全量持仓 + 配置开关 |
| `config.py` / `schemas.py` | 新增 `signal_live_sltp_guard_enabled`，**默认开启** |
| `api/signals.py` | `live_exit` 增加 `guard_enabled` |
| 前端 | 出场层卡片新增「止损巡检（缺单自动补挂）」开关 + 说明 |

三条安全约束：
1. **只补挂、不平仓**：巡检不调用任何平仓接口；
2. **已有止损跳过**：`has_protective_order` 命中即跳过，不会撤单重挂、不会叠加条件单；
3. **尊重方向开关**：该方向 `enable_{side}_sl_tp` 与 `enable_{side}_trailing_stop` 都为关闭时，
   巡检不补挂——用户主动关掉保护的选择不被覆盖。

频率：与超时平仓的 60s tick 解耦，每 300s 一次（一次 `fetch_open_orders`，可忽略的限流占用）。
