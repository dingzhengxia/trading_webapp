# 信号策略有效性验证报告

- 生成时间：2026-11-12
- 代码基线：`master @ eb144a4`（signal_config v2）
- 数据集：Binance 现货 K 线，BTC/ETH/SOL/BNB
  - 1h：3000 根（2026-07-10 → 2026-11-12，约 125 天），有效样本 1500 根/币
  - 4h：1200 根（2026-04-26 → 2026-11-12，约 200 天），有效样本 1000 根/币
- 方法：**用生产策略代码逐根回放**（`tools/strategy_probe/`），信号当根收盘产生、下一根开盘入场，
  统计 1/4/12 根（4h 为 1/3/6 根）后的收益，并减去「同时段同方向的平均漂移」得到超额（excess）。

---

## 0. 一句话结论

**当前这套是合格的信息提示系统，不是有正期望的交易系统。** 1h 上「关键位突破」在统计上显著亏钱
（持有 4 根平均 -31bp，t=-3.3，N=155），其余策略扣掉成本后在 0 附近；唯一像样的正结果（4h 关键位
做多 +97bp）样本只有 40 笔、单一时段，不足以支撑自动开仓。

## 2. 五个发现

### 发现 1：所有信号都呈「均值回归」特征，越拿越亏

1h `level_breakout`：持有 1 根 -1bp → 4 根 **-31bp** → 12 根 **-43bp**，单调恶化。
`trend_channel` 12 根 -39bp（t=-2.7）。说明信号在**冲动 K 线收盘后才确认**，入场时行情已走完，
后续 4–12 根回吐——典型「追高/追空」而不是「突破跟进」。

### 发现 2：`level_breakout` 在 1h 上是净损耗，且多空都亏

多 -32bp / 空 -31bp，两个方向同时为负，这不是运气问题，是逻辑问题：7/7 摆动点的「前高前低」
在 1h 上属于微观结构，突破后大概率回来。同一个策略在 4h 上做多 +97bp、做空 -55bp，
方向完全相反——更像是这个时段 4h 结构恰好有效，而不是策略稳定。

### 发现 3：`ema_cross` 实际上已经死了

125 天、4 个主流币、1h 只触发 **34 次**（约 0.07 次/币/天），4h 只有 **4 次**。
原因是 EMA120 + 1.0 ATR 缓冲 + 2.0x 量能三重叠加。它现在既提供不了信息，也提供不了交易，
不如显式决定：要么把缓冲降到 0.3–0.5 ATR，要么从白名单删掉。

### 发现 4：量能确认没有筛选价值

同样配置下把 `volume_confirm` 关掉：

| 策略 | 信号数 | 1h h4 超额 |
|---|---|---|
| `ma_breakout` 开启 2.0x 量能 | 98 | -1bp |
| `ma_breakout` 关闭量能 | 729 | **+9bp** |
| `level_breakout` 开启 1.5x | 155 | -31bp |
| `level_breakout` 关闭 | 225 | -21bp |

量能门槛砍掉了 70–85% 的信号，但没有让剩下的更准，反而在 `ma_breakout` 上砍掉了赚钱的那批。
量能更适合当**统计字段**（记录、分档复盘），而不是**硬门**。

### 发现 5：加「趋势过滤」不是万能药，两个周期结论相反

以收盘价 vs 同周期 EMA200 判定顺势/逆势：

| 周期 | 做多·顺势 | 做多·逆势 | 做空·顺势 | 做空·逆势 |
|---|---|---|---|---|
| 1h (h=4) | **-52bp** | -15bp | +1bp | +9bp |
| 4h (h=3) | **+39bp** | -47bp | -38bp | **+39bp** |

1h 顺势做多更差、4h 顺势做多更好——两个周期方向相反。此时硬加统一趋势过滤，只能在样本内
拟合出「1h 反着做、4h 顺着做」这种不可外推的结论。

## 3. 可优化项（按优先级）

| 优先级 | 动作 | 依据 |
|---|---|---|
| P0 | **自动开仓保持关闭**，直到有 ≥200 笔真实前视跟踪 | 目前没有任何配置能在扣成本后证明正期望 |
| P1 | **1h 停用 `level_breakout`**（保留 4h） | 多空双向 -31bp、t=-3.3；1h 微观结构无效 |
| P2 | **缩短持有/加时间止损**（4–6 根本金周期内未达目标即离场） | 1h 收益随持有期单调恶化（-1 → -31 → -45bp） |
| P3 | `ema_cross.atr_multiplier` 1.0 → **0.4**，或从自动开仓白名单移除 | 125 天仅 34 次触发，等于空转 |
| P4 | `volume_confirm` 改为**只记录不拦截** | 见发现 4，门槛无筛选价值 |
| P5 | 订单块的「测试区」提示加开关（同 `alert_on_test`） | 1h `ob_luxalgo` 125 天产生 420 条观望信号（0.84 条/币/天） |
| P6 | 产品化「信号前视收益」记录，2–4 周后按真实分布再调参 | 现在所有参数都只能靠推理，无反馈闭环 |

## 4. 这套数据说明不了什么（必须一并读）

- **只有 4 个主流币**，你的扫描池是 31 个（含小币）；小币波动结构完全不同，结论不可直接迁移。
- **用的是现货 K 线**（本机只能连 `data-api.binance.vision`），永续有资金费率与不同流动性。
- **单一市场状态**：125/200 天，恰好是震荡偏弱的一段；趋势市里突破类策略的表现会完全不同。
- **N 偏小**：单格 14–96 笔，t 值 1.5–2.5 的格子经多重检验后大多不显著，只有 |t|>3 的负结论较硬。
- **测的是固定持有期**，没有复现系统的 SL/TP 与 post-only 成交；真实结果会因止损被打断而不同。
- 未计资金费率、滑点、爆仓风险。

## 5. 复现方式

```bash
cd tools/strategy_probe
python fetch.py            # 拉 1h/4h K 线到 data/
python run_base.py         # 并行回放当前配置 -> res_base.csv（约 2 分钟 / 8 核）
python final.py            # 输出第 1 节表格
python analyze2.py         # 趋势对齐 + 策略汇总
```

脚本直接调用 `backend/app/signals/analysis/strategies.py` 的生产函数，只把
`_prepare_and_send_notification` 换成记录器（保留量能过滤、去掉真实时钟冷却，
否则回放会被冷却锁死）。改策略后重跑即可对比。
