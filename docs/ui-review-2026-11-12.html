设计评审 / Design review

交易终端 UI 评审与优化方案

本次评审覆盖 6 个视图、17 个组件、约 6 300 行前端代码（Vue 3 + Vuetify 3）。 结论先说：界面骨架完整、交互逻辑健全，但缺少设计系统这一层。所有视觉决策都散落在模板里， 导致色彩语义冲突、信息层级倒挂、以及浅色主题下的可读性缺陷。下面的方案不需要重写页面，只需要补上一层令牌 + 一轮结构收敛。

02

问题清单（按影响排序）

分三级：P0 会让人读错数据或看错状态；P1 增加操作成本与维护成本；P2 是打磨项。每条都附代码位置，方便直接对照。

P0

红绿一色双义：颜色同时表示"方向"和"盈亏"，且正负号不统一

同一个绿色既表示"做多"又表示"盈利"，同一个红色既表示"做空"又表示"亏损"。叠加 PnL 数字有的带 + 有的不带， 结果是「做空盈利」和「做空亏损」在视觉上几乎完全一致，只能靠凑近读数字。
证据
PositionsTable.vue:73  :class="item.pnl >= 0 ? 'text-success' : 'text-error'"  ← 无正负号
PositionsTable.vue:78  pnl_percentage > 0 ? '+' : ''  ← 有正负号（同一张表内不一致）
PnlSummary.vue:34 vs :47  多头有 '+', 空头没有  ← 同一组件内不一致
SignalsView.vue:1253  directionColor(): long→green, short→red
OpenHistoryPanel.vue:207  sideColor(): 硬编码 #1D9E75 / #E24B4A
影响
扫读错误风险；红绿色盲（约 8% 男性）完全无法判断盈亏方向——违反 WCAG 1.4.1「不能仅用颜色传达信息」。
方案
拆成两条互不干涉的通道：方向 = 箭头图标 + 文字 + 色；盈亏 = 正负号 + 色 + 等宽右对齐。统一由 utils/tone.ts 提供，禁止模板里再写三元表达式判色。
P0

没有主题令牌层，直接用 Vuetify 默认色板

createVuetify() 未配置 theme.themes，全站主色就是 Vuetify 出厂默认值。 这意味着品牌/产品调性为零，同时 success/error 被同时借去表示"操作成功"和"上涨/下跌"，语义被双重占用。
证据
main.ts:28-35  createVuetify({ components, directives, theme: { defaultTheme } })  ← 无 colors
实际取值（浅色 / 深色）
  primary  #1867C0 / #2196F3  ← Material Blue 出厂值
  success  #4CAF50 / #4CAF50
  error    #B00020 / #CF6679
ControlPanel.vue:22  <v-tabs bg-color="primary">  ← 整条饱和蓝 Tab 条
影响
改任何一个颜色都要全库搜索替换；无法做品牌化；"操作成功"的绿和"盈利"的绿无法独立调节。
方案
建三层令牌：primitive（原始色阶）→ semantic（bg/surface/border/long/short/up/down）→ component。Vuetify 主题只注入 semantic 层。
P0

浅色主题对比度不达标（盈亏数字与说明文字不可读）

深色主题基本没问题，但浅色主题沿用了同一套语义色，在白底上对比度直接跌破 AA 门槛。 而这两个色正好用在"盈亏数字"和"辅助说明"这两个最需要读清的位置。
证据
success #4CAF50 on #FFFFFF  ≈ 2.8 : 1  ← AA 正文需 4.5:1
text-grey #9E9E9E on #FFFFFF  ≈ 2.7 : 1
  使用处：SignalsView.vue:83, 95, 212, 225, 715；ProgressBar 等
对照：深色 #4CAF50 on #212121 ≈ 5.9 : 1 ✓
影响
浅色模式下盈亏数字与全部辅助说明弱到接近不可读，用户被迫切回深色。
方案
双主题各自定义独立取值（不是同一色加透明度）：浅色绿 #0E7A57、浅色辅助文字 #5F6975。加一个对比度断言脚本进 CI。
P1

信息层级倒挂：最该先看到的信号列表被压在 1000px 之下

SignalsView.vue 单文件 1 772 行，四张卡片纵向堆叠。首屏是 8 个同权重的 chip + 一整块"扫描范围"表单， 而用户来这个页面真正要看的东西——信号列表——排在第四张卡。同一张卡里"上次扫描时间"和"错误数"视觉权重完全相同。
证据
SignalsView.vue  1 772 行 / 4 张 PageCard
状态 chips：SignalsView.vue:29-56  8 个 size="small" variant="tonal" 平铺
信号列表：SignalsView.vue:661  ← 第 4 张卡，首屏之外
扫描范围表单：SignalsView.vue:100-150  ← 占据首屏主要面积
影响
每次看信号都要滚过一屏设置表单；设置项与监控项混在一起，误改配置的概率上升。
方案
拆成「KPI 状态条 + Tab」。首屏 = 4 个指标 + 信号列表；扫描范围 / 推送与开仓 / 前视统计各自一个 Tab。见第 05 节线框。
P1

组件变体混用：同一页面里 filled 和 outlined 并存

表单控件没有统一的 variant 与 density 规范。同一个文件里相邻的两个输入框，一个是默认 filled，一个是 outlined； 按钮则同时出现 tonal / text / flat / 默认四种。
证据
SignalsView.vue:115  扫描 TopN  density="compact" variant="outlined"
SignalsView.vue:188  推送倍数  默认 filled（同页同类输入）
ControlPanel.vue:41  默认 filled vs ControlPanel.vue:267  outlined
按钮：variant 出现 4 种，且"危险等级"无规则（清空信号=warning，批量平仓=blue-grey，平仓=error，反手=warning）
影响
视觉噪音累积成"未完成感"；危险操作的视觉强度与真实风险不对应。
方案
锁定：表单 = outlined + density="compact"；按钮三级（主操作 / 次要 / 破坏性），破坏性再分"需确认"与"已确认"。
P1

模式抽象滞后：PageCard 只统一了外壳，卡内小节复制了三份

PageCard 统一了 title + divider + text 的三段式，这是有效的。但卡内部"图标 + 小节标题 + 说明"的结构在 SignalsView 里手写了三次， 空状态有 5 种不同写法（v-alert text / v-alert tonal / 纯 text / 无 / 表格 no-data-text），加载态只有 ControlPanel 用了骨架屏。
证据
SignalsView.vue:92-97 / 162-172 / 222-226  同一段小节标题结构 × 3
空状态：SignalsView.vue:720  v-alert type="info" variant="text"
        ProtectionView  无
        PositionsTable.vue:69  no-data-text（表格内）
加载态：ControlPanel.vue:407  v-skeleton-loader（仅此一处）
影响
空态/加载态不一致造成布局跳动（CLS）；每加一个页面就多一份复制。
方案
抽 SectionHeader、EmptyState、PageSkeleton 三个组件；空状态必须带一个前进动作（CTA）。
P2

布局补丁散落：底部留白硬编码 + 白色边框写死

悬浮底栏的留白由每个页面各自 style 硬编码，数值还不一样；底栏边框写成了白色 12% 透明度，浅色主题下这条分隔线直接消失。
证据
TradingView.vue:3  paddingBottom: '80px'
SettingsView.vue:4  paddingBottom: smAndDown ? '128px' : '80px'
其它 4 个视图：无  ← 同一 App 内 3 种行为
AppDockFooter.vue:10  border-top: 1px solid rgba(255,255,255,0.12)
ProgressBar.vue:7  同上  ← 浅色主题下不可见
影响
换布局常量要改 5 个文件；浅色主题下浮层与内容粘连、边界丢失。
方案
在 v-main 统一加 --dock-h 内边距；边框改用 var(--c-border)。
P2

死代码与无障碍缺口

mobile.css 里仍在为底部导航写规则，但导航早已改成顶部抽屉；三个纯图标按钮没有可读标签。
证据
mobile.css:31-42  .v-bottom-navigation  ← App.vue 已无此组件
App.vue:102 注释自述「不再使用底部导航」  ← 规则未清
App.vue:10 / 15 / 24  纯图标按钮：只有 title，无 aria-label
icon 按钮默认 40px < 44px 触控建议值
影响
维护者误读；屏幕阅读器读出"按钮"三个字，不知道是主题切换还是日志。
方案
删除死规则；补 aria-label；.v-btn--icon 提到 44px。
03

色彩系统：从"借色"到"分层"

核心动作不是换配色，而是把颜色按职责分开。现在共有 5 种绿（success #4CAF50、green #4CAF50、#1D9E75、light-green-accent-3、green-darken-3） 和 4 种红在混用；收敛后只有 2 个语义槽：long（方向）与 up（盈亏）。二者今天可以取同一个值，但必须是两个可独立调整的变量。

04

排版与数据可读性

金融界面 80% 的字符是数字。现在全站没有一个等宽数字设置，表格每次刷新（10 秒一次）都会因为数字宽度变化而左右抖动；中文字体也没有显式声明，靠系统默认回落。

字体栈与字号阶梯

项现状建议
中文未声明，靠 Vuetify 默认 Roboto 回落-apple-system, "PingFang SC", "Microsoft YaHei", "Noto Sans SC"

同一列数字在一串刷新中会因字形宽度差异产生 1–3px 位移； 表格每 10 秒刷新一次，视觉上就是持续的轻微"跳动"。

另：SignalsView.vue 里 text-caption text-grey 被当作说明文字大量使用（约 12 处）， 12px 中文在深色底上已接近临界，浅色底上则直接不可读。建议说明文字固定 12px + --c-text-lo，并只在真的次要时使用。

7.2 语义映射 · 替换三处各自为政的判色函数

// frontend/src/utils/tone.ts（新建）
export type Direction = 'long' | 'short' | 'neutral'

// 方向：色 + 箭头 + 文案，三者同时给出
export const directionTone = (d: Direction) => ({
  long:    { color: 'long',  icon: 'mdi-arrow-up-bold',   label: '做多' },
  short:   { color: 'short', icon: 'mdi-arrow-down-bold', label: '做空' },
  neutral: { color: 'grey',  icon: 'mdi-minus',           label: '观望' },
}[d] ?? { color: 'grey', icon: 'mdi-minus', label: '—' })

// 盈亏：符号是主要信息，颜色是次要信息
export const pnlTone = (v: number) => ({
  color: v >= 0 ? 'up' : 'down',
  text: formatSigned(v),   // 永远带 +/-
})
// utils/format.ts 追加 —— 唯一允许的数字格式化入口
export const formatSigned = (v: number, digits = 2) => {
  if (!Number.isFinite(v)) return '—'
  const s = Math.abs(v).toLocaleString('en-US', {
    minimumFractionDigits: digits,
    maximumFractionDigits: digits,
  })
  return v < 0 ? `−${s}` : `+${s}`   // 用真正的减号 U+2212，比连字符更对齐
}

08

落地顺序与验收

严格按顺序做。令牌没落地就去改页面，等于在流沙上盖房子。

阶段范围验收标准
P0 令牌 新增 theme/index.ts、utils/tone.ts、styles/base.css；替换三处判色函数；补格式化的正负号 全库搜索 text-success/text-error 用于盈亏的地方归零；切换主题后所有数字列不抖动；红绿色盲模拟下仍能区分赚赔
P1 结构 抽 SectionHeader / EmptyState / PageSkeleton；SignalsView 改 KPI + 4 Tab；ProtectionView 同步收敛 SignalsView 文件行数下降 40%+；首屏能看到至少 5 条信号；空状态 100% 带 CTA
P1 规范 表单统一 outlined + compact；按钮三级化；危险操作分两阶 同页内不再出现 filled/outlined 并存；"批量平仓"等高风险操作有二次确认且主色为危险色
P2 打磨 统一 v-main 底部内边距；清 mobile.css 死规则；补 aria-label；44px 触控 6 个视图底部留白一致；浅色模式下浮层描边可见；axe 扫描图标按钮无 label 告警为 0
P2 守门 加一个对比度断言脚本（读 theme 文件，逐对计算 WCAG 比值），进 CI 任何新颜色若低于 4.5:1 直接构建失败——这是唯一能防止规则倒退的办法
一句总结：这套界面缺的不是审美，是约束。当"这个绿该用哪个"有唯一答案时， 六个视图自然会长成一套东西；没有约束时，每加一个功能就多一种随心所欲。
