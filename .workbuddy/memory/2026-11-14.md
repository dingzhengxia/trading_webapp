## 仓位保护「执行开关」自己弹回关 —— 根因与修复（上午）

- **现象**：仓位保护页「接管开仓端止盈止损」「连续移动止损」拨到开，约 10s 后自己变回关。
- **根因**：`useProtectionConfig` 的 `fetchStatus()` 每 10s（ProtectionView setInterval）
  无条件 `applyConfig(server.config)` 回填整包表单；而这些 v-switch 只绑 `form`，
  不点「保存参数」就没落库 → 下一轮轮询把值刷回旧值。
- **修复 1（脏值基线）**：新增 `saved` 基线 + `dirtyKeys/isDirty/revertChanges`；
  `fetchStatus(force=false)` 只在无未保存改动时回填表单（首次加载基线为空 → 不参与比较，
  不会误判）。`saveConfig` 走 `fetchStatus(true)`；`patchConfig` 成功后把 patch 的 key
  写入基线，避免开关被永久算成「未保存」而挡住轮询。
- **修复 2（开关即时生效）**：新增 `applySwitch(key, value)`（乐观写 + 失败回滚），
  ConfigForm 的 5 个执行开关全部改成 `:model-value` + `@update:model-value`，
  四布尔开关用 `booleanSwitches` 数组 v-for 渲染（避免 4 段重复模板）。
  数值参数仍需点「保存参数」，按钮在有未保存改动时变 warning 色并显示项数，旁边出现「撤销」。
- **enable_long_sl_tp 归属**：交易页 → 开仓设置 → 通用 → 「开启多头固定 SL/TP」
  （空头对应 enable_short_sl_tp）。它就是「开仓端固定 SL/TP」；
  「接管开仓端止盈止损」= take_over_external_stops，会撤掉这些 SL/TP/TS 条件单
  （exits.EXTERNAL_CONDITIONAL_PREFIXES = SL/TP/TS），先确认 PM_WS_SL_ 就位才撤。
- **验证**：vue-tsc --build 通过，eslint 干净；未跑 build/deploy（需用户 ./deploy.sh）。

## HelpTip 手机端说明被裁 → 移动端改弹窗（上午末）

- **现象**（用户手机截图）：点「?」弹出的说明卡片被推出屏幕，左侧正文被裁、无法读完。
- **根因**：桌面用 `v-menu location="top"` 把 320px 气泡锚在靠右的「?」上，小屏视口放不下，
  卡片一半在视口外（Vuetify 的 auto-shift 只保证锚点在视口内，不保证超宽卡片整体可见）。
- **修复**：`HelpTip.vue` 改成 `<component :is="mdAndUp ? VMenu : VDialog">`
  （`import { VDialog, VMenu } from 'vuetify/components'`，动态渲染必须显式引入）。
  桌面保持锚定气泡；≤959px 走居中 v-dialog，maxWidth 440、正文 max-height
  `min(60vh,480px)` + 内部滚动，并给显式关闭按钮（小屏点空白关闭不直观）。
  另：`overflow-wrap: anywhere`（文案里有 `PM_WS_SL_` 这类长串会顶宽卡片）、
  移动端正文 0.9375rem、`::after` 把 20px 的「?」点击区扩到 40px。

## ETH 保本止损被扫 + 平仓静默（下午）

- **现象**：ETHUSDC 多单 15:20:25 被「市价委托(已触发)」全平，实盈 +2.4645 USDC（≈0.11%），
  钉钉没收到任何消息。
- **定性**：订单类型带「已触发」= 交易所侧条件单成交 → 引擎挂在交易所的
  **兜底 STOP_MARKET（reduceOnly）**，不是引擎主动平仓（引擎主动平仓显示「市价委托」）。
  数学反推：2163.57 名义 / 1889.57 = 1.145 ETH；手续费 0.0021 BNB；净 +2.46
  ⇒ 开仓 ≈1885.2，止损落在 1885.2×1.002=1889.0（`breakeven_buffer_pct` 0.2%），
  成交均价 1889.57 → 典型「浮盈≥0.5R 后止损抬到保本，价格回踩被扫」。
- **为什么没通知（真 bug）**：`runner._sweep_lifecycle` 发现仓位消失时只 `ledger.delete`
  + 写一条 flat 事件，**既不 note_action 也不 send_alert**。引擎主动全平有推送
  （上次补的），交易所兜底单成交这条路径没有。
- **修复**：
  1. `_sweep_lifecycle` 删行前先读账本取 stop/last_price/entry/contracts →
     `_describe_disappearance()` 定性（最后价距 STOP ≤1% 判为止损触发，否则判手动平仓）
     → 写 flat 事件（带 triggered_stop/stop/last_price）→ note_action → 命中才 send_alert
     （手动平仓不推钉钉，避免批量平仓刷屏）。
  2. `_apply_stop` 事件带「建立/上移到保本·锁盈/档位推进 + 原价」，risk_model 的 stop
     动作加 `previous_stop`、`_stop_move_reason()` 定性。
  3. 新增 `GET /api/protection/events`（ledger.recent_events，DB 持久化跨重启）——
     以前台账只写不读，出事只能翻容器日志。
  4. 前端：`useProtectionConfig` 增 `events`（fetchStatus 里顺带拉）；保护页「最近保护动作」
     换成「最近保护事件」事件流（kind 徽章 + 兜底触发红字 + 可滚动），
     `formatEventTime()` 新增到 utils/format（今天只给时分，跨天给月日）。
- **校验**：pytest 427 passed（4 个失败为既有 test_exit_rules/test_signal_tracker 问题，
  stash 基线一致）；vue-tsc / eslint / build 通过。未部署。
- **给用户的调参建议**：`breakeven_trigger_r` 0.5 → 1.0，减少「刚有点浮盈就被保本扫掉」。
