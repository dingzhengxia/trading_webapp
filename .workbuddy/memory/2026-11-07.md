# 2026-11-07

## 钉钉配置改为读取项目目录 .env

背景：用户把 `DINGTALK_WEBHOOK_URL/SECRET`（及币安密钥）写在服务器 `/root/trading_webapp/.env`，
但 `deploy.sh` 用的是 `--env-file /root/config/.env`，容器也未挂载项目目录的 .env，导致网页一直显示「钉钉未配置」。

改动：
- `deploy.sh`
  - 新增 `PROJECT_DIR`（BASH_SOURCE 解析脚本所在目录），并 `cd "$PROJECT_DIR"` 后再 `git pull` / `docker build`。
  - `ENV_FILE="$PROJECT_DIR/.env"`；旧的 `/root/config/.env` 若存在且新文件缺失则自动 `cp` 迁移（`LEGACY_ENV_FILE`）。
  - .env 创建后 `chown` 给当前用户、`chmod 600`；检测 CRLF 并 `sed -i 's/\r$//'`（`--env-file` 会把 \r 注入，导致签名/密钥失效）。
  - STEP 5 启动前自检 `DINGTALK_WEBHOOK_URL` / `BINANCE_API_KEY` 是否为空并提示。
  - `docker run` 除 `--env-file` 外再 `-v "$ENV_FILE":/app/.env:ro` 兜底。
- `.dockerignore`：新增 `.env`、`.env.*`（保留 `.env.example`）、`data/`、`*.db*`。
- `.env.example` 注释说明「放项目根目录，与 deploy.sh / start.bat 同级」。
- `backend/app/core/env_loader.py`：docstring 更新为「项目根目录 .env 优先」，加载成功 `logger.info` 命中路径、未找到 `logger.warning`（不打印内容）。
- `frontend/src/views/ReportsView.vue`：提示文案改为「项目根目录的 .env（与 deploy.sh 同级）」，用 `<strong>` 而非 markdown 星号。

注意：`--env-file` 只在容器创建时读取，`docker restart` 不生效，必须重跑 `deploy.sh` 重建容器。

安全：用户截图泄漏了币安 API Key/Secret 与钉钉 access_token/加签密钥，已提醒轮换。
