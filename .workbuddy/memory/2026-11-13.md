## 傍晚：断路器误伤开仓链路修复（用户紧急反馈）

### 事故根因链
用户截图：AAPL/GOOGL/AMZN 限价单 → 撤单 -2011 "Unknown order sent"（订单已成交/已撤销，撤单打空）
→ 旧 RestGuardian 把业务错误当故障连续计数 → 5 次熔断 OPEN 30s → 熔断期 fetch_order_book(NORMAL)
被拒 → 开仓定价失败 RetriableOrderError → 执行子任务"断路器 OPEN"报错循环。
用户澄清：没有仓位 ≠ 没有订单活动——是信号自动开仓任务在挂单/撤单。

### 修复（backend/app/core/）
1. **rest_guardian.py**：新增 `_is_business_error`（ccxt.ExchangeError 类型判断 + -2011/-2013/-1013
   等文本兜底；429/418 优先归类限流）。业务错误：**不计 failures、不重试、立即抛出**——
   重试结果确定相同，且绝不因撤单打空熔断交易链路。网络/限流错误仍计数+重试+熔断。
2. **guarded_exchange.py**：`fetch_order_book`/`load_markets` NORMAL→HIGH（开仓定价/chase 让价/
   任务初始化必经读）。create_order/cancel_order/fetch_order 等原本已 HIGH 绕过熔断。
3. 新增 4 个测试（业务错误不重试不熔断/连续业务错误不熔断/ccxt ExchangeError/429 照旧计数），
   更新 test_guarded_exchange.py 优先级断言。全量 365 passed，12 个既有环境失败不变，零回归。

### 修复后语义
- 开仓/平仓优先级第一：下单/撤单/查单/持仓/盘口/初始化全部 HIGH 绕过熔断。
- 断路器只保护扫描/行情类（fetch_ohlcv LOW、fetch_ticker(s) NORMAL），防 429/418 IP 封禁。
- 注意：业务错误不重试是新行为，调用方自行决定是否重试（如 chase 循环）。

## 傍晚续：v2 幽灵仓位修复 + 删 v1 参数 UI + 3/4/5 接入 v2

### 关键发现
- 用户实际跑的是 **v2 引擎**（engine_version=v2，runner.py 四档减仓），不是 v1 engine.py！
  之前 #4 接管 / #5 连续追踪只接了 v1 主循环 → 用户视角"没实现"。
- **幽灵仓位 69 个 vs 实际 7 个根因**：v2 status() 读一仓一行账本全集，
  而 _sweep_lifecycle 对账依赖进程内存 previous_active —— 引擎重启后内存集合丢失，
  平仓后的账本行永久残留。

### 修复内容
1. **runner.py 幽灵行对账**：_sweep_lifecycle 改为账本全集 vs 本轮真实持仓（contracts>0）对账，
   不依赖内存；flat_confirm_sec 缓冲防漏报。踩坑：ledger key 是 'sym|side' 字符串、
   active 是 tuple，统一 split_key 成 tuple 再相减；disappeared 元素已是 tuple，
   不能再 split_key（否则 symbol 变成整 tuple 字符串）。status() 过滤 contracts<=0 兜底。
2. **v2 接入 #4 接管**：_prepare 每轮检查（幂等标志存账本行 + 60s 节流），每周期成功完成才置终态。
3. **v2 接入 #5 连续追踪**：新增 _v2_trailing_stop（plan.entry/risk 适配 tp_entry_price/tp_risk_distance
   字段 + min_move 防抖防每 3 秒撤重挂），决策后 patch/追加 stop action（黑天鹅仍优先压制）。
4. **_take_over_external_stops 返回值语义**：-1=守护端 STOP 未就位可重试，>=0=完成。
   v1/v2 调用处都适配（-1 不置标志下轮重试）。
5. **前端**：ConfigForm.vue 删 v1 核心参数组（TP1/TP2/躺平R、T1/T2/T3 结构回看）；
   执行开关组加"接管开仓端止盈止损"、"连续移动止损"、"连续追踪触发(R)"；
   useProtectionConfig.ts form/applyConfig 补 3 个新字段；types.ts 补类型。
6. 新测试 test_protection_v2_sweep.py 9 个（幽灵行清理/重启模拟/live 保留/status 过滤/追踪防抖）。
