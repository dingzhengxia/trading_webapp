# 2026-11-20 工作日志

## 新功能：自动开仓按日线趋势过滤方向

用户需求：日线空头趋势只开空、多头趋势只开多。

**关键决策——复用现有趋势算法**：项目已有 `analysis/trend.py::get_current_trend`（三线 EMA 严格排列 fast>medium>long，参数走 signal_config.json 的 `trend_ema_long` 组 26/50/120，用于钉钉文案）。我先写了双线 EMA20/50 的独立实现，对比后**改为复用现有算法**：口径与钉钉推送文案一致（不会"推送写空头趋势却开多单"）、三线判定更严谨、少一套参数。判定周期固定日线（timeframe_to_minutes('1d')=1440>60 → 自动走 trend_ema_long 组）。

### 实现
- 新增 `backend/app/signals/trend_filter.py`：TrendFilter（list→DataFrame→get_current_trend 映射到 long/short/neutral）+ make_trend_provider 装配器。30 分钟 TTL 缓存（neutral 不缓存，故障恢复后重试）；行情经 MarketDataService（RestGuardian 合规）；异常/数据不足 → neutral **放行**，绝不阻塞开仓链。
- `auto_trader.py` 过滤链插入步骤 2.5（方向白名单后）：trend≠neutral 且与 direction 不符 → skip。trend_provider 为可选参数（旧调用方不受影响）。
- `service.py`：`_get_trend_filter()` 单例 + `_signal_trend_provider()`（full_symbol 优先于 base symbol 查 K 线）；真实开仓与纸面跟踪（tracker）共用同一判定。
- 配置：`signal_auto_trade_trend_filter_enabled`（默认开）+ `signal_auto_trade_trend_cache_seconds`（1800）；schemas 加对应 Optional 字段。
- 前端：PushAutoPanel 加"日线趋势过滤"开关（单字段 patch 保存、失败回滚），types/signalsData/help 同步。
- 测试 `backend/tests/test_trend_filter.py` 13 个：涨跌合成 K 线判定、数据不足/异常降级、缓存、过滤链（逆向 skip/顺向 open/neutral 放行/异常放行/开关关闭/未装配 provider）。
