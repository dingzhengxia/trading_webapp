## 保本止损加 ATR 缓冲 + 追踪收紧（commit a8b3f27）
用户反馈「0.5R 很容易被扫到，吃不到大增幅」。查代码后确认真实轨迹不是「每 0.5R 上移」：
- 0.5R → 止损 = 开仓价 +0.2%（死数），离现价 ~0.55%，1h ATR≈1% 时一次普通回撤就扫掉；
- 0.5R~1.8R 完全钉在保本价：`trailing_start_r=1.0` + `trailing_atr_mult=2.5`，
  浮盈 1R 时 `peak−2.5ATR` 还在开仓价下方，`max()` 取保本位 → 等于没跟随；
- 1.8R 之后才按 2.5 ATR 跟随，宽度又偏大。
用户选定方案 A（ATR 跟随），保本触发保持 0.5R。改动：
- `risk_model._stop_action`：保本位 = 开仓价 ± max(0.2%, 0.3×ATR)，新增参数 `breakeven_atr_ratio=0.3`；
- `V2_DEFAULTS`：`trailing_start_r` 1.0 → 0.5、`trailing_atr_mult` 2.5 → 1.5；
- `runner.load_config` 加 `LEGACY_DEFAULTS` 迁移：老配置里等于旧默认 (2.5/1.0) 的值视为没改过；
- `/api/protection/config` 加 `breakeven_atr_ratio` 范围 (0,5)；前端参数设置新增该项、追踪默认 1.5。
- 口径：浮盈 1R → 止损 0.5R，2R → 1R，4R → 3R；回撤容忍 ≈1.5 ATR。

## 止盈「回调才减仓」的两处缺陷（commit b0e34b9）
用户反馈 11:03 BTC「怎么回调这一点就给我减仓了」。台账 + 持仓复查结论：
- 那是**分批止盈 TP1**，不是止损：TP1 = 入场 64,536.08 + 1R(968.04) = 65,504.12。
- **缺陷 1：止盈走了 maker 优先（GTX 挂卖一价）**。价格已越过目标位，maker 挂单在回落中
  永远不成交 → 10s 撤单重挂更低的卖一价 → 最后在 65,5xx 成交（比目标位低、比峰值更低）。
  叠加：`_apply_reduce` 入口 `attempts[tag]=now` 让双源价差失败后等 90s 才重试；未成交只写
  logger，用户侧零感知。修：新参数 `tp_taker_first`(默认 true) → `exits._limit_reduce_with_maker_retry(skip_maker=True)`
  挂对手价吃单；双源失败改短冷却；未成交/暂缓写 `skip` 事件（60s 节流）。
- **缺陷 2：止盈量按初始仓位比例算，一刀清零**。tp_ratios 是给 base 设计的，但结构破位
  T1/T2/T3 已先减掉大半，11:03 只剩 0.014，再卖 base*0.25 → 0.003（标称 25%，实际 -79%）。
  修：`tp_reduce_by_remaining`(默认 true) → 止盈量 `current * ratio`；结构破位档保持 base 口径。
- 事件文案补「，目标 TP{n} {价}」。
- 前端：参数设置→执行开关新增两个开关；API 加布尔校验。
- 测试 tests/test_tp_execution.py 4 例（含 skip_maker 挂 bid / 默认值护栏）；全量 484 passed
  （4 个既有失败 test_exit_rules / test_signal_tracker）；已推 master b0e34b9。**未部署。**
- 口径沉淀：**止盈是「到价即走」，减仓是「按固定份额」——两者不能用同一套挂单策略**。

## 止盈重构：预挂 post-only 单，全程不吃单（TP v3）
用户口径（本轮原话）：「止盈应该要用对手价挂单，不允许吃单，唯一唯一的吃单只有黑天鹅；
现在止盈有点粗糙了，重新设计一下」。**推翻 b0e34b9 的 tp_taker_first（到价吃单）**——
上一轮"回调才减仓"的真正根因不是"该不该 maker"，而是"到价之后才下单"这个结构。

### 旧结构的两个死结
1. 3s 轮询发现价格越过 TP → 才下单 → 下单往返期间价格已回落；
2. 到价后只剩两种选择：站在卖一排队（回落就不成交）或吃单（付 taker + 滑点）。

### 新结构：把单子提前挂到交易所
- 建仓后立刻挂「当前这一档」的 reduceOnly 限价单，`timeInForce=GTX`（post-only）。
  价格到档由交易所撮合，成交价就是 TP 价、费率是 maker，引擎不参与撮合。
- 挂单价 `risk_model.tp_limit_price`：多单 max(TP, 卖一)、空单 min(TP, 买一)。
  未到价挂 TP（在盘口之上等涨），已越过则跟到盘口被动侧——**两种都在被动侧，配合 GTX 双重保险，
  物理上不可能吃单**。GTX 被拒（-5022）→ 用最新盘口重挂，仍拒则本轮放弃，绝不打市价。
- 一次只挂当前一档（不是三档全挂）：插针只卖掉 TP1 这 20%，后面档位等价格再走到。
  成交后同一轮补下一档（`runner._verify_tp_order` + `_place_next_tp_order`）。
- 数量 `tp_order_qty` = min(初始仓位×档位比例, 当前剩余×tp_slice_cap(0.5))。
  分母仍是初始仓位（档位比例就是按它设计的），`tp_slice_cap` 兜住"结构减仓砍到很小再一刀清零"。
- 仓位变了但单子还挂着（结构减仓/部分成交）→ `_tp_order_stale` 判定差 >5% 就撤单重挂。
- 新周期第一轮 `tp_sweep_pending` 扫一次交易所残留的 PM_WS_TP_ 单；全平/仓位消失也撤。

### 阶梯参数（"粗糙"的另一半：前端之前根本没暴露 v2 止盈参数）
- 旧：1R/2R/3R 减 25/30/30，keep 15%。1R 正好是保本止损刚推到位的位置，第一波冲高就卖 1/4。
- 新：**1.5R / 2.5R / 4R 减 20% / 25% / 30%，保留 25% 给追踪止损**（`tp_keep_ratio` 0.25）。
- 前端新增「止盈阶梯」折叠面板（R 倍数 ×3、比例 ×3、保留仓位、单档上限），
  删掉 tp_taker_first / tp_reduce_by_remaining 两个开关；仓位卡片加「TPn 挂单中」chip。
