## 止盈重构：预挂 post-only 单，全程不吃单（TP v3）
用户口径（本轮原话）：「止盈应该要用对手价挂单，不允许吃单，唯一唯一的吃单只有黑天鹅；
现在止盈有点粗糙了，重新设计一下」。**推翻 b0e34b9 的 tp_taker_first（到价吃单）**——
上一轮"回调才减仓"的真正根因不是"该不该 maker"，而是"到价之后才下单"这个结构。

### 旧结构的两个死结
1. 3s 轮询发现价格越过 TP → 才下单 → 下单往返期间价格已回落；
2. 到价后只剩两种选择：站在卖一排队（回落就不成交）或吃单（付 taker + 滑点）。

### 新结构：把单子提前挂到交易所
- 建仓后立刻挂「当前这一档」的 reduceOnly 限价单，`timeInForce=GTX`（post-only）。
  价格到档由交易所撮合，成交价就是 TP 价、费率是 maker，引擎不参与撮合。
- 挂单价 `risk_model.tp_limit_price`：多单 max(TP, 卖一)、空单 min(TP, 买一)。
  未到价挂 TP（在盘口之上等涨），已越过则跟到盘口被动侧——**两种都在被动侧，配合 GTX 双重保险，
  物理上不可能吃单**。GTX 被拒（-5022）→ 用最新盘口重挂，仍拒则本轮放弃，绝不打市价。
- 一次只挂当前一档（不是三档全挂）：插针只卖掉 TP1 这 20%，后面档位等价格再走到。
  成交后同一轮补下一档（`runner._verify_tp_order` + `_place_next_tp_order`）。
- 数量 `tp_order_qty` = min(初始仓位×档位比例, 当前剩余×tp_slice_cap(0.5))。
  分母仍是初始仓位（档位比例就是按它设计的），`tp_slice_cap` 兜住"结构减仓砍到很小再一刀清零"。
- 仓位变了但单子还挂着（结构减仓/部分成交）→ `_tp_order_stale` 判定差 >5% 就撤单重挂。
- 新周期第一轮 `tp_sweep_pending` 扫一次交易所残留的 PM_WS_TP_ 单；全平/仓位消失也撤。

### 阶梯参数（"粗糙"的另一半：前端之前根本没暴露 v2 止盈参数）
- 旧：1R/2R/3R 减 25/30/30，keep 15%。1R 正好是保本止损刚推到位的位置，第一波冲高就卖 1/4。
- 新：**1.5R / 2.5R / 4R 减 20% / 25% / 30%，保留 25% 给追踪止损**（`tp_keep_ratio` 0.25）。

## 止盈挂单每 3 秒「撤单→重挂」（commit 71d7896）
用户截图：币安订单历史里 BTCUSDC 每 3s 一张「限价委托/卖出、只减仓、只做Maker、
已取消」，价格数量完全一样（71,515.0 / 0.001 BTC），刷满一屏。

**根因**：`_tp_order_stale` 拿「未取整的理论量」比「已按交易所网格取整的挂单量」，
再套 5% 相对误差阈值。TP1 理论 0.0015、网格 0.001 → 挂单为 0.001，
|0.001-0.0015| = 33% > 5% → 每轮都判「数量不符」→ 撤 → 重挂 → 仍不符 → 死循环。
只要理论量不在网格上（几乎必然），循环永不停止；顺带每 3s 两张 REST/仓位。

**修复**（三处口径统一 + 防抖）：
- 新增 `runner._desired_tp_qty`：与下单共用 `amount_to_precision` 取整（含取整后反超
  持仓的兜底）。挂单与校对都走它 → 两边同口径，能真的相等。
- `_tp_order_stale(order, want)` 只做数值比较（容差 1e-6 相对值）；`want<=0`（仓位
  已小于最小下单量）判该撤，撤完由 `_place_next_tp_order` 标记该档完成。
- 部分成交不再把 `qty` 改成剩余量（否则下轮比对又不等）；`qty` = 这张单总共卖多少，
  已成交记 `filled`，剩余量交给交易所维护，不撤单重排。
- 新增 `tp_rearm_min_interval_sec`(8s)：同一档 8s 内最多重挂一次；唯一例外
  「挂单量 > 当前持仓」（reduceOnly 超仓会超卖）必须立刻撤。

**教训**：任何「本地理论值 vs 交易所实际值」的比较，必须先把两边换成同一精度网格再比，
5% 这类相对阈值在「数量只有 1~2 个 lot 步长」时毫无意义。

## 加仓后不重建风险周期（ETH 兜底 1,775 掉到真实开仓价之下）commit cc87044

基准，只紧不松，所以重建不会把已有止损放松。

## 止盈口径第三次改版：引擎判定「先突破、回落才卖」（commit 57472b6）
用户原话：「比如 100，要超过 100 以后跌回 100 才止盈，而不是直接挂在 100」；
「是需要程序检查啊，突破以后回落就止盈，不是让你挂单在交易所」；

这推翻了 5caff38 的「预挂 post-only 卖单」：把单子挂在 TP 上 = 把判断权交给撮合，
插针碰一下就成交，后面的大行情吃不到，而且和 3 秒轮询的定位是两套并行逻辑。

**现在的规则（全在 risk_model.decide，纯函数可测）**：
1. `tp_armed`（sticky）：peak ≥ TP×(1+`tp_breakout_confirm_pct`，默认 0.1%) 才登记突破；
2. 已登记且价格回到 TP（多跌回/空涨回）→ 出 reduce 动作，`tps=[i]`；
3. 一次跌穿多档时**从高档往低档扫**，先卖离现价最近的那档（否则会按 TP1 贱卖 TP2/TP3）；
4. 单轮只卖一档；结构破位与止盈同一轮互斥，破位优先。

`tp_limit_price`、`tp_verify_interval_sec`、`tp_rearm_min_interval_sec`。

## 止损止盈整体重做：单状态机 + 规模锚 + ATR 止损阶梯
用户原话：「好好给我设计一下止损和止盈，要考虑中途人为加仓、减仓的情况，
要精确 稳妥 现在你弄的什么乱七八糟的 一会这有问题一会那有问题」。

**根因**：老逻辑用「风险周期」包住一切，`_is_new_cycle` 里把「均价变了/数量变了」
当成新周期 → 整行 `new_state` 重建。后果：ETH 兜底 STOP 落到真实开仓价之下、
BTC 标称减 25% 实砍 79%、已完成档位被重置、灾难线跑飞到 −11.29%。

**四条不变量（写进 docs/sl-tp-design-2026-11-15.md）**
1. 一个仓位只有一个状态，加仓是状态转移（rebase），不是新周期；
2. `size_anchor` = 历史最大持仓量，只增不减，所有分批比例都以它为分母；
3. 止损只朝盈利方向移动，唯一例外是 rebase 那一轮（`tag='stop:rebase'`）；
4. 灾难线 = `risk_max_pct`，T4 永远在它之内；减仓量单一口径
   `min(S×ratio, contracts×(1−keep_frac))`。

**几何**：`d_min=max(risk_min_pct,0.8ATR%)`，`d_max=max(risk_max_pct,1.5×d_min)`，
T1 由结构位+0.5ATR 定并 clamp 到 `[d_min, 0.85×d_max]`，T2~T4 = T1→灾难线等分。

**止损阶梯全按 ATR**（旧按 R，R 与波动脱钩）：保本 2ATR、追踪起点 2.5ATR、
宽度 1.5ATR、离现价呼吸 `max(0.6ATR, 0.3%)`。

**人工干预识别** `detect_intervention`：均价变 >2bp 必是加仓（币安平均成本法）；
数量变 >0.2% 且均价不变 = 加/减仓；加仓反解成交价
`p=(E_new×q_new−E_prev×q_prev)/Δq`。加仓走 `rebase_plan`（保 tiers_done/tp_done/peak，
重算档位/R/TP/灾难线，清 `tp_armed`）。

**实测**：BTC 灾难线 −11.29% → −6.00%；ETH 加仓后 STOP 回到均价之上。
后端 510 passed（4 个既有失败与本次无关），前端 vue-tsc/eslint/build 全通过。
