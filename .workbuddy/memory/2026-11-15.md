## 三个线上问题修复（commit 03a88bb）
- **信号页展开纸面跟踪后底部 Tab 被撑开（只看得到两个菜单）**：根因是宽表没横滚容器
  → 页面比视口宽 → 手机浏览器把布局视口拉宽 → `position:fixed` 的 `.app-tabbar` 铺满整条宽度。
  修法：base.css 加全局 `.table-scroll`（width/max-width/min-width:0 + overflow-x:auto），
  `html { overflow-x: clip }`（clip 不建滚动容器，不影响 sticky）；PaperTrackingPanel 3 张表 +
  RiskSettingsPanel 仓位表补容器，SignalListPanel/OpenHistoryPanel 改用同一个类。
  **教训：以后任何 v-table 都必须包 `.table-scroll`，否则手机上会拉坏固定底栏。**
- **手动撤销交易所 STOP 后不补挂 / 止损不移动**：根因 = v2 决策只读账本 `state['stop']`，
  从不核对交易所。新增 `runner._exchange_stop_price()`（默认 `stop_verify_interval_sec=15s`，
  复用 orders_cache）；`Snapshot` 增 `exchange_stop/exchange_checked`；
  `_stop_action` 交易所无单 → 出 `stop:restore`，有单 → 以交易所价为基准并在 decide 里回写账本；
  `_apply_stop` 对 restore 强制刷新挂单列表防重复创建；补挂写台账 + 钉钉推送。
  止损移动本就存在：0.5R→保本、每减一档→下一档、止盈锁盈、1R 后 ATR 追踪，
  推进需 ≥ max(价格×0.15%, ATR×0.15%)。
- **「填 3000 开出 5000 多」**：按订单反推（ETH 1498.67 + BNB 1493.96 + BTC ≈2000）
  = 总 5000 的 40/30/30 默认分配 → 服务端当时收到的就是 5000，3000 没落库。
  已加：`_trading_loop_task` 下单前把「开仓计划 N 币 合计 X USD（每币明细）」写进界面日志；
  抽屉摘要改为按方向显示「多 3 币 3.0k / 空 2 币 2.0k」（原来「总价值=多+空」是误读源头）。
  待用户核对：交易页 → 开仓记录 → 11-14 22:05 那批的「总 X USD」。
- 测试：新增 tests/test_stop_restore.py（5 例）+ test_protection_v2.py 加 4 例；

## 更正：「填 3000 开出 5000」= 权重键对不上清单（commit 4796dc4）
昨天那条「3000 没落库」的结论是错的。用服务器 `/api/trading/open-history` 的 snapshot 复查：
- 11-14 21:12~22:05 那几批：`total_long_position_value=5000`、`long_coin_list=[BNB,BTC,ETH]`，
  而 `long_custom_weights` 存的是 `{AAPL/AMD/AMZN/GOOGL/NVDA/SPCX/TQQQ 各 14.29}`（美股 7 币均分）。
- `_normalize_custom_weights` 按当前清单过滤 → 7 个键全落空 → `weights={}` → `_default_allocation`
  → BTC 40% / ETH 30% / 其余均分 → 2000/1500/1500。所以「均分是我设的」和「BTC 40%」同时成立。
- 权重弹窗还帮了倒忙：键对不上 → 各项算 0 → 自动均分显示 33.33/33.33/33.33，看着像已生效，
  实际没保存。用户就这样以为「我设的是均分」。
修法：新增 `utils/weights.ts`（复刻后端默认分配）；`WeightConfigDialog` 改用 `useDraftSettings`
共享草稿 + 保存即 `commitDraft()` 落库；弹窗在无自定义权重时显示**后端真实默认（40/30/均分）**并提示；
`ControlPanel` 对「权重键不在清单」直接告警；后端 `stale_weight_note()` 进开仓日志 warning；
`_allocate_by_weights` 修掉「总和≥100 时后加的币权重=0 被静默跳过」。
线上数据已改：`long_custom_weights = {BTC 33.34, ETH 33.33, BNB 33.33}`（总数 2000 → 667/667/666）。
**教训：凡是「用户设置 vs 后端行为」相关，必须先取到实际生效值（API/DB 快照），不要从界面反推。**
