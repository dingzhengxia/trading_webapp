# 2026-11-24

## 信号列表趋势标签（backend，commit 356a60c）

用户截图质疑「信号里做多做空混杂，不是说好方向要跟趋势匹配吗」。

排查结论：
- 趋势过滤只装在自动开仓闸门（`auto_trader.py` 第 2.5 道，`trend_provider`），
  信号生成/列表展示/钉钉推送都不经过它，所以列表多空混杂是设计行为；
- 服务器当时 `signal_auto_trade_enabled=False`，那道闸根本没在跑；
- 用币安日线 EMA26/50/120 复核 78 条信号：顺势 19、逆势 30（多头趋势做空 11 +
  空头趋势做多 19）、neutral 27、震荡 2。21 个币里 15 个日线空头。

改动：
- `signals/service.py` 新增 `attach_daily_trend()`：给信号就地补 `daily_trend`
  与 `trend_ok`（True 顺势 / False 逆势 / None 不适用），并发 4、整体 8s 超时，
  单 symbol 失败只缺字段；
- `GET /api/signals` 返回前调用它；
- `trend_filter.py` 新增 `neutral_cache_seconds`（默认 0 保持开仓链路现行为），
  展示层用独立实例（60s），避免震荡币被 10s 轮询反复重拉日线；
- 新增 `tests/test_signals_daily_trend.py`（5 例）+ `test_neutral_cached_when_configured`。

测试环境（Python 3.13，pydantic 2.7.1 无 wheel 装不上）：
- `python -m venv backend/.venv`，装不锁版本的 fastapi/pydantic/ccxt；
- pandas-ta 0.4.67b0 的 `from posix import pread` 仍需手工 patch
  `site-packages/pandas_ta/overlap/alligator.py`（Windows 无 posix）；
- 全量：7 failed / 561 passed，7 个是既有基线失败（纸面跟踪未开仓、settings 表未初始化）。
