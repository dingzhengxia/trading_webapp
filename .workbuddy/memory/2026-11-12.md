## 修复：币种信号钉钉推送缺失（报告能收到、币种信号收不到）

- 根因：Phase 2 合并时按 MERGE_PLAN §1 排除了 monitor 的 notification_service，
  `backend/app/signals/` 全链路（emit_signal -> signal_queue -> SignalStore）只做
  「内存缓冲 + 网页展示 + 自动开仓」，没有任何钉钉推送调用。只有 `reports/` 与
  `protection/notifier.py` 会调 `reports.dingtalk.send_markdown`，所以只有报告能收到。
- 修复：
  - 新增 `backend/app/signals/notifier.py`：把同一批信号合并成一条 markdown 推送
    （MAX_BATCH=20，单条正文上限 1200 字，红涨绿跌配色），复用 `reports.dingtalk`
    （webhook/secret 只读环境变量、加签、18000 字截断）。
  - `backend/app/signals/service.py::_consume_loop`：一次排空队列成批，store.add 后
    用独立 task 推送（不阻塞自动开仓），再逐条跑 auto_trader。
  - 新增设置项 `signal_dingtalk_enabled`（默认 True），与总开关 `dingtalk_enabled`
    同时为真且 `DINGTALK_WEBHOOK_URL` 已配置时才推送。
  - `api/signals.py` 的 GET /api/signals 增加 `push` 字段（configured/enabled/子开关）。
  - 前端 SignalsView 增加「币种钉钉推送」开关（webhook 未配置或总开关关闭时禁用），
    types.ts 增加 SignalPushStatus，已重新构建 dist。
  - 测试：新增 tests/test_signal_notifier.py；test_signals_api 断言更新；全量 195 passed。
- 部署注意：改的是后端 + 前端，需重跑 deploy.sh 重新 build（Dockerfile 会重建前端）。
